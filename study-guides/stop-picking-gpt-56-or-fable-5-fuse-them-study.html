Stop Picking GPT-5.6 Sol OR Claude Fable 5. Fuse Them.

IndyDevDan · IndyDevDan · July 20, 2026 · ~26 min

Study Guide

Overview

IndyDevDan opens with a rejection of the industry's framing: everyone wants a single winner between GPT-5.6 Sol and Claude Fable 5, but he argues that "picking is the mistake." His thesis is model fusion: instead of selecting one model, you combine multiple models into a coordinated team of agents so you get the intelligence and context windows of both. The winning mindset, he says, is and not or - "don't select compute, combine compute." The video walks through a custom fusion harness built on an extensible coding agent, demonstrating three slash commands across two live problems.

An Old Pattern With New Names

Dan stresses that model fusion is not new. The same idea has been called architect-editor, then prompt chaining, then agent chaining, and today Devin, OpenRouter and others call it model fusion. He claims to have run this pattern for years across hundreds and thousands of agents, and that most engineers already do a version of it without naming it. The goal is a tight, coordinated two-agent team rather than an "unchecked lone wolf."

The Three Commands of the Fusion Harness

The harness exposes three custom commands. /opinion runs two agents in parallel to gather independent perspectives (it has no write or edit tools, so agents only respond). /fusion combines and consolidates the best results: after both models produce work, a dedicated fusion agent using the same model as the architect merges the outputs and reports consensus, divergence, and what was discarded. /auto-validate is the most powerful command - it writes a validation gate before the work is even started.

In the auto-validate flow, the builder (GPT-5.6 Terra) sits idle while the validator (Claude Sonnet 5) writes a raw validation script that proves the work is done and includes fail commands that feed corrective feedback back to the builder. Dan frames this as attacking the second constraint of agentic engineering - review (the two constraints being planning and reviewing). Because he owns the harness, he can even make it so the builder cannot edit the gate file.

Demo One: Best scikit-learn Models

Running /opinion on "top three scikit-learn models," the two agents work side by side. GPT-5.6 Terra finished in 4.5 seconds (9K tokens in, 300 out, about 3 cents); Sonnet 5 took roughly double the time and cost about a cent more. Both agreed on random forest, XGBoost, and logistic regression. Running /fusion showed full consensus with a small, complementary (not contradictory) divergence that the fusion model kept, and nothing discarded. Dan's line: "Relativity is the best benchmark" - the value is seeing your agents compared head to head.

Demo Two: Bulk-Inserting a Million SQLite Rows

The harder, more realistic problem: insert over a million rows into an SQLite database in a fast, memory-efficient way, as a reusable solution rather than a one-off vibe-coded script. Dan runs state-of-the-art models at X-high mode - Fable 5 as architect, GPT-5.6 Sol as builder. On /opinion, Fable reported a 300X speedup while Sol found 250-1000X and 400-2000X candidates. /fusion combined the scripts into a benchmark, surfacing a set-based CTE approach as the speed winner (up to ~1000X, one result cited as a 560X speedup over native SQLite auto-commits) and WAL-tuned generation as the memory winner. Cost varied run to run (Sol was about twice as expensive as Fable here after an eight-minute run; Fable was 10X more expensive in an earlier one).

Key Concepts

  • Model fusion: combine multiple models' intelligence and context windows instead of choosing one provider, model, or tool.
  • Harness engineering: owning a customizable, extensible agent harness is what removes false limits; "whoever owns your agent harness owns your results."
  • Three value creators in the age of agents: engineers, agents, and raw code.
  • Two constraints of agentic engineering: planning and reviewing - auto-validate targets review by writing verification before execution.
  • Divergence is the point: value comes from a range of perspectives, "not 10 Johns" but a John, a Sally, a Tim - the same reason a fused team of distinct models beats duplicates.
  • Single node in a larger workflow: the fusion harness fits inside one agent node of an AI developer workflow (ADW) / software factory, tying back to his prior video dismantling "loop engineering."

Practical Takeaways

  • Stop picking a single model; run two and fuse their outputs to make better engineering decisions.
  • Use a repeatable flow: /opinion to scout, /fusion as an unofficial planning step, /auto-validate to test and build in one pass.
  • Write the validation gate before the work so you can prove a unit of work is done and reduce review burden.
  • Build additional patterns into your own harness: /debate (N rounds), /parallel (run both agents at once), /coordinate (agents discuss then build).
  • Prefer relative comparison of agents (speed, tokens, cost side by side) over abstract benchmarks.
  • Own or build your harness so you are not blocked waiting on Claude Code, Codex, or Open Code to ship a feature.
