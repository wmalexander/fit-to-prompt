CVSS 8.1 v3.1Researchers: 9.2 v4.0CVE-2026-114938Java

Java4Shell: a bug in Java's Base64 decoder can let a stranger run code on Jenkins, Jira, Keycloak and more

Oracle and the OpenJDK project fixed a memory bug in the fast Base64 decoder that Java uses on newer Intel and AMD chips. It affects Java 17.0.6 and later, plus Java 21, 25 and 27, but only on x86-64 servers with AVX-512 VBMI (Intel Ice Lake and newer, AMD Zen 4 and newer). ARM servers are not affected, and neither are Java 8 and 11 apart from one Oracle performance build. A bad Base64 string, such as a login header or SAML token that is decoded before anyone is logged in, can write past the end of a buffer. The researchers who found it (Calif) say they got code running with no login against Jenkins, Jira, Confluence, Keycloak, Artifactory and PingFederate under default settings, and with a login against Kafka, Solr, Elasticsearch, Gerrit and Spinnaker. They have not published their exploit code, other labs have reproduced crashes and a memory leak but not code running, and Canada's Cyber Centre knows of no attacks. Wiz says it built a working proof of concept in about two hours. NVD shows Oracle's 8.1 score; the researchers rate it 9.2 on the newer v4.0 scale.

Fixed builds: Oracle 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1. Per Aikido, Amazon Corretto has fixes (17.0.21.1.2, 21.0.13.1.2, 25.0.5.1.2, 27.0.1.1.4), Eclipse Temurin had no confirmed fix, and per The Hacker News Red Hat's fixes were still being prepared.

DoUpdate every Java 17, 21, 25 and 27 install to your vendor's fixed build, starting with internet-facing Jenkins, Jira, Keycloak and Artifactory. Where you cannot yet, add -XX:-UseBASE64Intrinsics to the JVM options (Wiz says it removes the bug, with some speed cost). To see if a Linux host has the chip features, run grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(avx512f|avx512bw|avx512vbmi|bmi2)$'; all four lines must appear for the host to be exposed.

Sources: The Hacker News · Aikido fixed-version table · Wiz Research · NVD
ExploitedCVSS 9.8 v3.1CVE-2026-129448CVE-2026-82384Apache Roller

Apache Roller before 6.1.6 runs an attacker's code before checking who is calling, and Apache says it is being exploited

Per Apache's record in NVD, Roller's XML-RPC endpoint accepts extension data types and unpacks them before it checks who sent the request, so a stranger can run code on the server. The record says 4.0.0 through 6.1.4 are affected, and the earlier entry for the same bug (CVE-2026-82384) listed 6.1.5. Apache states the bug is being actively exploited. It is not in CISA's exploited list yet.

DoUpgrade Roller to 6.1.6 or later. If you cannot yet, set enabledForExtensions to false in WEB-INF/web.xml, then check your logs for unexpected XML-RPC requests.

Sources: NVD record from Apache · NVD, earlier entry
ExploitedCVSS 9.4 v4.0CVE-2026-115731Puppet Enterprise

CISA lists a Puppet Enterprise bug where any agent certificate can be used to run code on the Puppet Server

Per NVD, Puppet Server's report-handling code unpacks untrusted data, so a client holding any CA-signed agent certificate can run code on the server by sending a crafted report. If your certificate authority signs requests automatically without strong checks, a stranger on the network can get such a certificate. CISA added it to its exploited list on November 17 and gave federal agencies until December 1. I could not find fixed version numbers in the sources I could read.

DoFollow Perforce's mitigation instructions for your Puppet Enterprise version, and turn off autosigning unless requests are strongly verified. Check which hosts hold agent certificates you do not recognize.

Sources: NVD · CISA KEV catalog

WordPress & PHP watch

CVSS 9.8 v3.1CVE-2026-107904JoomlaPHP

Joomla's Easy File Uploader before 2.9.7 lets a stranger upload a PHP file and run it

Per NVD, one upload request with no login and no CSRF token can place a PHP-runnable file in the Joomla web root. This is a Joomla extension from valorapps.com, not WordPress. NVD has not finished its review, and I found no report of exploitation.

DoUpdate Easy File Uploader to 2.9.7 or later, or uninstall it. Look in the Joomla web root for PHP files you did not put there.

Sources: NVD
CVSS 8.7 v3.1CVE-2026-110782ComposerPHP

The SimpleSAMLphp SAML2 library 6.2.2 and 6.2.3 can accept an unsigned login message from the wrong identity provider

Per GitHub's advisory, this is an incomplete fix for an earlier bug. When the HTTP-Artifact binding gets a signed outer reply that wraps an unsigned login response, the library returns the inner response without checking it. An attacker who controls one trusted identity provider in a federation with several can then pass off a response for a different provider. Single-provider setups are far less exposed. I found no report of exploitation.

DoUpdate simplesamlphp/saml2 to 6.2.4 (or 7.0.0-rc2 on the 7.x line), then run composer why simplesamlphp/saml2 to find every app that pulls it in.

Sources: GitHub advisory · NVD

Apache httpd

Still open: Apache httpd 2.4.55 through 2.4.70 has an HTTP/2 bug that can lead to code running

Nothing new from httpd today, so this carries forward from November 11. Per NVD, a shared-resource race in mod_http2 (CVE-2026-119618, 8.1 v3.1) can lead to code running. Upgrade to 2.4.71, or set Protocols http/1.1 until you can. No new Node.js or React advisories were posted today.

Sources: NVD
Next.jsReact

The Next.js team explains why advisories are piling up and how it is adding AI review

Per the Next.js team (so this is a vendor describing its own product), AI has made old bugs cheap to find: of the 51 vulnerabilities found this year, 70% sat in code at least a year old and 43% in code three years or older. Many came from the image libraries Next.js depends on. The team now runs a bug bounty, an internal triage bot, a Trail of Bits audit and an AI review of every pull request. Releases ship about once a month and are announced ahead of time, and the dev server now warns when your installed version has a known flaw.

Sources: Next.js blog

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

Supply chainPyPIPython

Microsoft's agent-framework package on PyPI had two poisoned releases that steal cloud and CI credentials

Versions 1.26.1 and 1.26.2 of agent-framework, Microsoft's package for building AI agents in Python, went up 33 minutes apart on November 17 (roughly 8:35 to 9:20 p.m. UTC) and have been quarantined. Each adds a .pth file that runs on every Python start, even if nothing imports the package, so it also runs when you launch pip. It collects environment variables, credential files (.npmrc, .netrc, .git-credentials, Docker and Azure CLI configs), Azure DevOps and managed-identity tokens, and in 1.26.2 GitHub Actions tokens, then posts them to a webhook.site address. The package gets about 190,000 downloads a month, per The Hacker News. How the attacker got publishing access is not yet known.

DoSearch lockfiles, images and CI logs for agent-framework 1.26.1 or 1.26.2 and pin to 1.26.0. On any machine that ran them, rotate every credential from a clean system (stored files and cloud tokens), review Azure and GitHub Actions sign-in logs, and search proxy and DNS logs for webhook[.]site.

Sources: Socket · The Hacker News · Aikido · StepSecurity

DockerSecrets

Cloud keys left in public Docker Hub images were used within 8 seconds in a research test

Stony Brook researchers planted fake AWS, OpenAI and Anthropic keys in 300 images across eight registries. The first AWS key was used 7.86 seconds after publishing, the median was about 51 seconds, and all 100 AWS keys were used within 15 minutes. Scanners read the image layers directly without running the image. Revoke any key that ever shipped in a public image.

Sources: BleepingComputer

AI × security

AI-assisted attacksGoogle GTIG

Google says attackers have an AI tool that finds and exploits web app bugs with no human involved

Google's Threat Intelligence Group found a multi-agent tool called exploit_agent on an exposed staging server. Per SecurityWeek's summary of the report, it compares patched and unpatched web application code, finds the flaw, writes an exploit and runs it automatically. The server also held stolen data and scripts for scouting and planting web shells, and evidence pointed to French media and entertainment sites and the education sector. Google also reports groups using frameworks such as Artex, Cairn, CyberStrikeAI and PentAGI to turn newly patched bugs into attacks faster, and a Chinese group building its own automated attack tool.

DoTreat the gap between a patch and an attack as shrinking: apply web-facing security updates within days, and watch for new files in web roots.

Sources: SecurityWeek
