CVSS 9.2 v4.0CVE-2026-123007CVE-2026-123633NGINX

NGINX before 1.30.7 and 1.31.9 can let a stranger run code on the server when HTTP/2 is on

NGINX fixed five bugs on November 18 that its vendor F5 says can lead to code running on the server. NVD scores all five 9.2 out of 10. The two worst need HTTP/2 turned on. CVE-2026-123007 is a memory bug in HTTP/2 flow control that is present in every release from 1.9.5 (2015) through 1.31.8. Wiz says it got code running against a server that only served plain static files. CVE-2026-123633 hits servers that pass HTTP/2 requests on to a backend, when the worker is running low on connections. The other three need other setups: CVE-2026-123634 needs a proxy address built from a variable plus a mirror or Server Side Includes request, CVE-2026-121810 needs HTTP/3, and CVE-2026-113425 needs the mail proxy. Code that runs this way gets the rights of an NGINX worker, not root. F5 says attackers can run code when address randomization (ASLR) is off or can be bypassed, and Wiz says it bypassed it in tests. A proof of concept is public on GitHub, but The Hacker News says its notes limit it to a demonstration in a fresh Docker container. Neither F5 nor the researchers report attacks, and none of these CVEs is in CISA's exploited list.

Turning HTTP/2 off blocks only CVE-2026-123007 and CVE-2026-123633. It does not block the other three. Per Aikido, ingress-nginx is affected by CVE-2026-123633 and will not get a patch. NGINX Plus is affected too, and F5 has its own fixed builds. Distribution packages may carry the fix without changing the version number.

DoUpgrade open source NGINX to 1.30.7 (stable) or 1.31.9 (mainline), or install your distribution's patched package after reading its security notice for these CVE numbers. Start with servers that face the internet and have http2 on in the listen or http2 on; setting. If you cannot upgrade today, turn HTTP/2 off as a stopgap, and plan to move off ingress-nginx.

Sources: nginx.org advisories · Wiz Research · The Hacker News · Aikido · NVD · NVD · NVD · NVD · NVD
Security releaseWordPress7.1.5

WordPress 7.1.5 fixes 20 security issues, including a no-login path to code running on the site

WordPress says this is a security release and asks you to update right away. Patchstack counts 20 fixes, 18 of them real vulnerabilities and 2 hardening changes. The worst one lets a visitor with no account plant a malicious Template Part block, and WordPress says that can lead to code running on the site; Patchstack says it needs an editor to open the content. Other fixes cover SQL injection in meta queries and in Customizer previews, stored cross-site scripting from comment shortcodes, a no-login denial of service through batched XML-RPC pingbacks, and a multisite bug that lets a site Administrator take over a Super Admin account. The fixes were not given CVE numbers in the sources I read.

DoUpdate every site to WordPress 7.1.5 today, and on multisite confirm the network and every site report 7.1.5. Sites with background updates may already have it.

Sources: WordPress.org · Patchstack
ExploitedCVSS 9.8 v3.1CVE-2026-90817REDCap

CISA says attackers are using a REDCap bug that lets a stranger run code through a public survey link

Per NVD, REDCap 13.3.0 and later has a bug in survey routing and data import that lets someone with no account run code on the server. The attacker needs the secret hash from a valid public survey link. CISA added it to its exploited list on November 18 and gave federal agencies until November 21. I could not find a fixed version number in the sources I could read.

DoCheck the REDCap consortium site for the vendor's fixed release and install it. Until then, think about taking public survey links offline, and look in your web logs for odd data import requests that start from survey URLs.

Sources: NVD · CISA KEV catalog

Core, plugins, themes, PHP and the frameworks on top of it

Today, 14:00 UTCPHP

PHP ships critical security fixes for every supported version today

PHP will release security updates for all supported versions on November 19 between 14:00 and 14:30 UTC (9:00 to 9:30 AM Eastern). The top severity is critical, and PHP says the critical bugs need non-default or uncommon setups. Fixed version numbers are not published yet. One expected fix is for a code-running bug in session upload progress that PHP described in October. Until the release, set session.upload_progress.enabled=0, then upgrade as soon as the numbers appear.

CVSS 9.8 v3.1CVE-2026-127021Plugin

Flamix Bitrix24 and WooCommerce Products Sync before 1.7.0 lets anyone write a PHP file to the site

Per NVD, one request with no login can write a file with a name and path of the attacker's choice, which then runs as PHP. I could not find an install count. Update the plugin to 1.7.0 or remove it.

CVSS 9.8 v3.1CVE-2026-124990Plugin

Masteriyo LMS 3.5.1 and earlier unpacks untrusted data in its course importer

Per NVD, a stranger can exploit this only on sites that allow instructor sign-up and guest checkout and sell a course, which is not the default. On a default install it needs an Author account or higher. The record lists no fixed version, so check the plugin's changelog for a release newer than 3.5.1, and turn off instructor sign-up until you have it.

CVSS 9.9 v3.1CVE-2026-129048Plugin

WP Photo Album Plus through 9.3.06.003 has a code injection bug

Per NVD, the plugin allows remote code inclusion in versions through 9.3.06.003. The record gives no detail on who can trigger it and no fixed version, and it is still awaiting NVD analysis. If you run it, look for a newer release and consider deactivating the plugin until one is out.

Node.js, React & Apache watch

The runtime, the front-end framework and the servers under a lot of the web

ExploitedCVSS 9.8 v3.1CVE-2026-90436Apache Axis 1.x

CISA says attackers are using a flaw in Apache Axis 1.x, which will never be fixed

Per the Apache record in NVD, Axis 1.x through 1.4 loads and builds a class named inside an incoming SOAP error message before any login check runs. If a suitable class is on the application's classpath, a stranger can run code. CISA added it to its exploited list on November 18, with a November 21 due date for federal agencies. Axis 1 is end of life and the project does not expect to release a fix.

DoFind apps that bundle Axis 1.x (look for axis-1.4.jar in your builds) and move them to Apache Axis 2 or another SOAP library. If you cannot, Apache points to a patch commit you can build into your own copy.

Sources: NVD · Apache patch commit · CISA KEV catalog

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

UpdateRuby

Ruby 4.0.10, 3.4.13 and 3.3.14 fix seven memory bugs, and some have proof-of-concept code-running exploits

Ruby's team says seven bugs in its regular expression engine and in changing the case of strings affect Ruby 3.3.13 and earlier, 3.4.0 through 3.4.12, and 4.0.0 through 4.0.9. They know of proofs of concept that run code for some of them. The risky pattern is an app that compiles regular expressions or changes the case of text that a visitor controls. CVE numbers were requested but not yet assigned, so Ruby uses GitHub advisory IDs. Ruby 3.2 and earlier are end of life and will not get fixes.

DoUpgrade Rails and other Ruby apps to 4.0.10, 3.4.13 or 3.3.14, and plan to leave Ruby 3.2 and earlier.

Sources: Ruby security advisory
CVSS 7.5 v3.1CVE-2026-71481Composer

ALTCHA PHP 2.0.0 to 2.0.2 skips its signature check when the signature is missing

In altcha-org/altcha, the verify step skips the signature check if the challenge has no signature, even when a secret is set. An attacker can issue their own easy challenge, solve it, and pass the bot check. The fix is in 2.0.3.

DoRun composer update altcha-org/altcha to get 2.0.3 or later.

Sources: GitHub advisory · NVD
CVSS 7.5 v3.1CVE-2026-73864npm

npm package install-artifact-from-github 1.6.0 and earlier loads downloaded code without checking it

The install script downloads a prebuilt native add-on and loads it with no checksum or signature check. Anyone who can alter that download can run code in your build. The fix is in 1.7.0.

DoSearch lockfiles for install-artifact-from-github, and move to 1.7.0 or later where it is a direct or nested dependency.

Sources: GitHub advisory · NVD
ResearchBrowsers

A new HTML element lets script run in innerHTML even when the equals sign is blocked

Guest researcher Masato Kinugawa published a payload that uses the selectedcontent element to run script where filters strip the equals sign. PortSwigger says it no longer works in Chrome since version 153 but still works in Safari 27.2. Do not rely on blocking one character to stop injection into innerHTML; sanitize or avoid it.

AI-found bugs

Wiz used its own AI scanner to find the NGINX bugs, and says AI shortens the gap between disclosure and attack

Wiz says it found both NGINX HTTP/2 flaws with Wiz Atlas, its AI code scanning harness, and used two AI models to confirm the impact. Four other teams reported the same bugs on their own. This is a vendor describing its own tool, so treat the claim about speed as its view. WordPress's 7.1.5 notes also credit Anthropic with two of the reports, a reflected XSS in the legacy media popup and a REST API leak of private taxonomy terms.

CVSS 8.8 v3.1CVE-2026-63129MCP server

mssql-mcp write tools build SQL from text an AI agent supplies, so a bad prompt can change your data

The @connorbritain/mssql-mcp packages put table names and WHERE clauses straight into SQL. An agent that reads untrusted text can be steered into sending SQL that updates or deletes more than intended. Fixed in core and server 0.6.0, reader and writer 0.5.0. Use a database login with only the rights the agent needs.

Worth reading

SANS: treat nginx2shell, PHP2Shell and Java4Shell as the new normal, not emergencies

Johannes Ullrich writes that SANS stays at Infocon Green because you cannot stay on alert all the time. His honeypots see many Java attacks but none using Java4Shell yet. His advice is that you cannot patch a large estate before an exploit appears, so automate patching for less critical systems and build procedures for a steady stream of critical bugs.

  • Watch for the PHP security releases at 14:00 UTC and set session.upload_progress.enabled=0 until you upgrade.
  • If you run REDCap, install the vendor's fix or take public surveys offline; CISA's due date is November 21.
  • Find apps that bundle Apache Axis 1.x and plan to replace it.
  • Upgrade Ruby to 4.0.10, 3.4.13 or 3.3.14, altcha-org/altcha to 2.0.3 and install-artifact-from-github to 1.7.0.
