CriticalDrupalNot yet exploited

Drupal installer bug can let a stranger take over a site; update to 10.6.22, 11.3.22 or 11.4.13

Drupal core ships an install.php file. The Drupal Security Team says that under specific conditions an attacker can use it to try to reinstall the site, which can end in a site takeover or code running on the server. A visitor with no account can try it. Some attack paths fail if the web server cannot write to or change permissions on settings.php. The team warned on Monday that exploits could appear within hours or days. Anthropic's OSS Scanner found the bug. I could not confirm a CVE number in NVD yet, so none is printed here.

Drupal also fixed a second bug rated moderately critical. It lets an administrator reach code execution, but only if the site also deserializes untrusted data because of another flaw. Sites behind the paid Drupal Steward firewall are covered against the known attack paths, and Drupal still advises updating.

DoUpdate Drupal core to 10.6.22, 11.3.22 or 11.4.13 today. If you cannot, block /core/install.php in the web server configuration or in the .htaccess file in the web root, and make settings.php read-only for the web server user.

Sources: BleepingComputer, quoting the Drupal advisory · The Hacker News
CVSS 9.2 v4.0CVE-2026-129496CVE-2026-129289PHP

PHP 8.5.13, 8.4.28, 8.3.37 and 8.2.36 fix seven critical flaws, and two can reach an ordinary WordPress host

PHP released all four versions on November 19 with 18 fixes, seven of them rated critical at 9.2. Most need unusual settings. Patchstack's analysis says two deserve attention this week. CVE-2026-129496 is a memory bug that a stranger can trigger on a non-thread-safe build (the usual kind with PHP-FPM) when PHP writes a startup warning to a file-based error log, for example because of a bad date.timezone value. Patchstack says researchers crashed a worker on default settings and showed code execution. CVE-2026-129289 lets a stranger smuggle a forged request to PHP-FPM, but only if the front end reuses FastCGI connections. That is fastcgi_keep_conn on in NGINX or enablereuse=on with Apache mod_proxy_fcgi, and neither is the default. WordPress opens php://input on every REST request, so the application side of the condition is always met.

This is a PHP update, not a WordPress update, so installing a new WordPress release does nothing for it. The other five critical bugs need session handling, upload progress or PHP 8.5 error settings that most sites do not use.

DoMove to PHP 8.5.13, 8.4.28, 8.3.37 or 8.2.36 through your host or your container image. Before then, search your NGINX and Apache configuration for fastcgi_keep_conn and enablereuse and turn them off, and fix any PHP startup warnings in your error log.

Sources: php.net release announcement · Patchstack · NVD · NVD

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 9.8 v3.1CVE-2026-14492Plugin

WP Duplicate through 1.1.11 lets a logged-in user run code on the server

Per NVD, the plugin's batch file save step has a loose comparison that can be tricked, plus a file path that is not checked, so an authenticated user with custom-level access or higher can write files and run code. It only applies once the site owner has finished the plugin's setup. NVD lists no fixed version and I could not find an install count. Check the plugin page for a release newer than 1.1.11, and remove the plugin if you only used it for a one-time migration.

CVSS 9.4 v4.0CVE-2026-129396CVE-2026-129410Joomla

Joomla extension Visforms has two bugs that let a backend user run PHP

Per NVD, the CSS editor in Visforms does not restrict file names or paths, and calculation fields run their formulas through PHP eval() without checking them. Both need a backend login. They affect versions through 5.6.4 and 6.2.1 depending on the bug. Update Visforms to its newest release, and review who has backend access to forms. NVD still has both records as deferred.

Node.js, React & Apache watch

The runtime, the front-end framework and the servers under a lot of the web

CVSS 9.8 v3.1CVE-2026-114516Node.js

Etherpad before 3.3.3 lets anyone with no login read any file on the server

Etherpad is a shared editor built on Node.js. Its file handler for /static/* turns backslashes into slashes after the safety check has already run, so a crafted request with encoded backslashes can climb out of the folder. The handler runs before any login check. GitHub says an attacker can read settings.json, which holds the admin password, and from there reach code execution through the admin plugin installer. Affected versions are 1.8.14 up to 3.3.3.

DoUpgrade ep_etherpad-lite to 3.3.3. If your instance faced the internet, change the admin password and any keys in settings.json.

Sources: GitHub advisory · NVD
Nothing new todayCVE-2026-129448Apache

No new Node.js, React or Next.js advisories; the Apache Roller bug is still being exploited

The Node.js security feed, the React blog and the Next.js blog posted nothing in the last day. Apache's own notice says the Roller bug covered on November 18 is being exploited, and that it hits versions 4.0.0 through 6.1.4 through the XML-RPC endpoint before login. Turning XML-RPC off in the admin screen does not stop it. Apache says to upgrade to 6.1.6 or later, and 6.1.7 fixes 15 more bugs. Details are in SecurityWeek and NVD.

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

CVSS 7.4 v3.1CVE-2026-132825Ruby on Rails

Ruby2Shell can let a stranger run code on a default Rails app, and GitHub Enterprise Server has no fix yet

Veria Labs found that changing the case of text in some older single-byte encodings, such as ISO-8859-1 and Windows-1252, writes one byte past the end of a buffer. Rails and classic-style Sinatra do this in their default setup. It affects Ruby 2.4.0 through 3.3.13, 3.4.0 through 3.4.12 and 4.0.0 through 4.0.9. NVD scores it 7.4, and Aikido calls it critical. No attacks have been reported, but the researchers plan to publish their exploit in about a week. Per Veria's table, GitLab, Mastodon, OpenProject, Discourse and Chatwoot have fixed releases. GitHub Enterprise Server 3.22.5 and earlier has none yet.

DoUpgrade Ruby to 3.3.14, 3.4.13 or 4.0.10 and redeploy, and update GitLab to 19.6.1, 19.5.8 or 19.4.10. If you run GitHub Enterprise Server, limit who can reach it until GitHub ships a fix. Ruby 3.2 and older have no fix, so plan the move.

Sources: Ruby advisory · Veria Labs · Aikido · NVD
ExploitedCVSS 9.8 v3.1CVE-2026-123890VMware vCenter

VMware vCenter login bypass was used in attacks for two months before the patch

A flaw in the VMware Directory Service lets someone with network access to vCenter skip the login and get administrator access. Google's Mandiant says a suspected China-linked group it calls Armory Castle used it as a zero-day starting in early September, to run commands and copy files such as the directory database. Broadcom has not itself confirmed the attacks. Broadcom calls this an emergency update and says there is no workaround, although limiting network access to vCenter helps. It is not in the CISA exploited list as of today.

DoApply the fixes in Broadcom advisory VMSA-2026-0009: vCenter 9.1.1.0200, 9.0.2.0200 or 8.0 U3m, per NVD. Until then, keep vCenter off any network that web servers and developer machines can reach.

Sources: BleepingComputer · SecurityWeek · NVD
CVSS 9.8 v3.1CVE-2026-132891CI

JetBrains TeamCity before 2026.2, 2026.1.4 and 2025.11.8 can run code from an outside pull request

Per NVD, code execution was possible through external pull requests. The record has no more detail and I could not read the JetBrains advisory. If your TeamCity builds pull requests from forks, update to 2026.2, 2026.1.4 or 2025.11.8, and until then stop building outside pull requests automatically.

CVSS 9.3 v4.0CVE-2026-63412Composer

jane-php/open-api-3 before 7.12.0 can run code when it generates a client from a hostile OpenAPI file

The generator writes parameter names straight into code comments, so a name that closes the comment can add its own code to the generated client, and that code runs when the client is created. GitHub lists several sibling advisories for the same package, all fixed in the same release. Only teams that generate clients from OpenAPI files they do not control are at risk. Run composer update jane-php/open-api-3 to get 7.12.0 or later.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

CVSS 9.3CVE-2026-76807CVE-2026-77359MCP

A website you visit can drive the Todoist and Jupyter MCP servers running on your laptop

Both servers listen on a local web port without checking which website is calling, so a malicious page can use DNS rebinding to send commands to them. Per NVD, Todoist MCP Server before 10.3.3 lets a page write and delete Todoist data through its optional HTTP mode, scored 9.3 on version 3.1. Jupyter MCP Server before 1.0.3 leaves management routes open in standalone HTTP mode, so a page can take over the Jupyter backend, scored 9.3 on version 4.0. GitHub also lists a similar bug in an Obsidian MCP server. This is the same class of bug for any coding agent tool that exposes a local HTTP port.

DoUpgrade @doist/todoist-mcp to 10.3.3 and jupyter-mcp-server to 1.0.3. Use the stdio mode instead of HTTP where you can, and check that any local MCP server you run rejects requests with an unexpected Host or Origin header.

Sources: Todoist advisory · Jupyter advisory · NVD · NVD
AI attackARTEX

The European Commission says an AI hacking tool was used in an attack on its staff systems

The Commission confirmed that the first signs of an attack appeared on October 22 and called it an AI-generated campaign. POLITICO reported that CERT-EU found the open-source AI platform ARTEX in use, which the FBI warned about last week. Payroll, leave and other staff services were down for more than 10 days. The Commission says it has no evidence of a broad data breach. The FBI says some intrusions with the tool went from first contact to privileged access in under three hours, which leaves little time to react to alerts.

  • Ask your host for PHP 8.5.13, 8.4.28, 8.3.37 or 8.2.36, and turn off FastCGI connection reuse until then.
  • Apply Broadcom VMSA-2026-0009 to vCenter and limit network access to it.
  • Upgrade Ruby to 3.3.14, 3.4.13 or 4.0.10 and redeploy Rails apps.
  • Upgrade local MCP servers (Todoist 10.3.3, Jupyter 1.0.3) and prefer stdio over HTTP.
