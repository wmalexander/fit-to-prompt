ExploitedCVSS 8.1CVE-2026-123158OpenSSH

CISA now lists the OpenSSH "SSHole" long-password bug as exploited

This is the bug from the last two briefings. NVD says OpenSSH before 10.6p2 on Linux, when it uses musl libc without PAM, accepts any password between 256 and 1,024 characters for some accounts, and Alpine Linux is its example. CISA added it to the Known Exploited Vulnerabilities catalog on November 9 with a November 12 deadline for federal agencies. The Hacker News reports that GreyNoise saw its first attempt on November 7 and has since seen six source addresses carry out 18 attack chains, which included reading password hashes and root SSH keys, asking cloud metadata services for credentials, and editing the authorized_keys file to stay in. In at least one case the attacker installed a Python command-and-control agent.

DoUpgrade OpenSSH to 10.6p2 or later on Alpine and any other musl-without-PAM host that accepts SSH from the internet, including container base images you build on. If a host was exposed, check its authorized_keys files and look for new keys or accounts.

Sources: The Hacker News · CISA KEV catalog · NVD
ExploitedChrome

Chrome fixes its eighth exploited zero-day of the year, a memory bug in its XML code

Google says it knows an exploit exists in the wild for a use-after-free bug in Chrome's XML component, a flaw where the browser keeps using memory it already released. Google has not shared who is being attacked or how. The fix is in Chrome 157.0.8103.50 for Linux and 157.0.8103.50/.51 for Windows and Mac, and the Android build carries the same fixes. The bug has a CVE number, but it was not in NVD when I checked, so I am not printing it here.

DoOpen chrome://settings/help, let Chrome update, and relaunch it. Do the same for Edge, Brave and other Chromium browsers when their updates land.

Sources: BleepingComputer · Chrome Releases
ExploitedCVSS 9.8CVE-2026-102895GPUStack

GPUStack, the AI model server, can be taken over by anyone who can reach it

NVD says versions before 2.2.0 treat a request that looks like it came from the same machine as the built-in administrator. Behind a same-host reverse proxy, or with a made-up X-GPUStack-Real-IP header, a stranger can make users and API keys, read cloud secrets, and run code. It was added to CISA's catalog on November 9, and The Hacker News says the fix shipped in July.

DoUpgrade GPUStack to 2.2.0 or later, and rotate any worker or cloud keys on an instance that was reachable from the internet.

Sources: The Hacker News · NVD
ExploitedCVSS 9.8CVE-2026-116779CVE-2026-123218FreeSWITCHIBM Aspera

Two more bugs joined the exploited list: FreeSWITCH calls and IBM Aspera Faspex

CVE-2026-116779 affects FreeSWITCH before 1.11.3. A user whose chat message is accepted can run FreeSWITCH API commands, which NVD says reach operating system commands, and inbound chat is on in the stock profiles. CVE-2026-123218 affects IBM Aspera Faspex 5.0.0 through 5.0.19, where a signed-in user can send a crafted message and gain full administrator rights. Both were added to CISA's catalog on November 9. These matter most to teams that run their own voice or file-transfer servers next to their web stack.

DoUpgrade FreeSWITCH to 1.11.3 or later. For Aspera Faspex, install IBM's November fix as described in its advisory, since NVD does not name a fixed release.

Sources: The Hacker News · NVD · NVD

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 9.8CVE-2026-123751WordPress

WP Duplicate, up to 1.1.11, lets strangers write files and run code

NVD says the plugin does not check a request token and does not check the path or type of uploaded files, so an unauthenticated visitor can write files to the server. The NVD entry itself says the bug is being exploited, but it is not in CISA's catalog and I found no second source. I could not find a fixed version, so remove the plugin and look for new .php files in the uploads folder.

CVSS 9.8CVE-2026-115237WordPress

Grand Job, up to 1.2.1, lets anyone reset an administrator's password

NVD says the plugin does not properly check the password reset code, so an unauthenticated attacker can set any account's password and take over the site. NVD lists no fixed version and the only source is NVD. Not reported as exploited. Remove the plugin and check your administrator list for accounts you do not recognize.

CVSS 8.1CVE-2026-76877WordPress

WPML, up to 4.9.7, can let a stranger sign in as another user

NVD says the cross-domain sign-in step used when each language has its own domain builds its token on the logout page, where no user session exists, so the token is the same for everyone for up to 12 hours. That can let an attacker sign in as a victim. It only applies to sites that run a separate domain per language. NVD does not name a fixed release and its analysis is deferred, so open the WPML changelog and update to the newest version. Not reported as exploited.

CVSS 8.2CVE-2026-120513WordPress

Everest Forms, up to 3.6.2, lets strangers delete files in the uploads folder

NVD says an unauthenticated visitor can delete files under wp-content/uploads, but only when the Save and Continue add-on is active. On a hardened Apache setup, deleting the uploads .htaccess file can turn PHP execution back on there. The WordPress.org page lists over 100,000 active sites. NVD names no fixed version, so update to the newest release and read its changelog. Not reported as exploited.

Nothing new today, and Node.js security releases are due tomorrow

The Node.js project says new 26.x, 24.x and 22.x releases arrive on or shortly after Wednesday, November 11, and that the worst issue fixed is rated high. End-of-life versions are always affected. Block out time tomorrow to update. I saw no new React, Next.js or Apache httpd advisories today.

CVSS 9.8CVE-2026-125120npmMongoose

Mongoose countDocuments() skips the sanitizeFilter protection

NVD says that before 6.13.11, 7.8.12, 8.24.3 and 9.9.2, countDocuments() ignores the sanitizeFilter setting, so a query object sent by an attacker is treated as query operators. The effect described is a wrong count, which can matter if your app makes an access decision from that count. The 9.8 score comes from NVD's rating, and the only source is NVD. Not reported as exploited. Update Mongoose to one of the fixed versions.

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

Supply chainnpmDesktop app

The bee-js poisoning also hit the Swarm Desktop app, and its auto-updater spread it

Yesterday's briefing covered the poisoned @ethersphere/bee-js 13.3.0. Socket's write-up adds that the same release pipeline also published a trojanized Swarm Desktop 0.56.2 on GitHub, and that the Windows and Apple Silicon builds reached users through the app's auto-updater. The npm package was published by the project's own trusted-publishing job with valid provenance, and npm removed it about 75 minutes later. The desktop release stayed up for about eight and a half hours, and the Mac build was signed and notarized. Socket says the loader reuses command-and-control infrastructure from an earlier campaign against Open VSX extensions. Socket sells security tooling, and the download counts come from its own analysis.

DoIf anyone installed Swarm Desktop 0.56.2 or bee-js 13.3.0, treat that machine as compromised and rotate its secrets. Pin bee-js to 13.2.0 until a clean release is published.

Sources: Socket
Supply chainHosting

Attackers hijacked the cPGuard update channel to push a backdoor

The Hacker News quotes OPSSHIELD, the maker of the cPGuard web security suite, saying an attacker used stolen credentials on November 2 to get into its update servers and sent out a malicious script through the normal update channel. The attacker got in through the company's billing app. The reports I read do not say which versions or how many sites were affected. If you run cPGuard on a cPanel host, check the vendor notice and look for files you did not expect.

Supply chainHosting

A fake Control Web Panel server file hides a backdoor named CWPdoor

XLab, quoted by The Hacker News, says a script called cwpsrv_update.sh swaps the real cwpsrv web server for a trojanized copy that waits for a specially built request, runs the commands in it, and keeps that request out of the access logs. The reports do not say how the script reaches a server. If you run Control Web Panel, compare the cwpsrv binary against a known good copy and reinstall it from the vendor if it differs.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

AI attackMCPHosting

A German web host says attackers got in through its AI assistant connector

Mittwald, a hosting provider for web agencies, says an attacker abused a flaw in its Model Context Protocol (MCP) server, the connector that lets customers link an AI assistant to their hosting account. The attacker went unnoticed for eight days and compromised 56 customer projects. Mittwald does not yet know whether the flaw is in its own code or in the open-source MCP libraries it uses. The company says the logs show steps taken seconds apart and believes AI tools were used, but it has given no other evidence, so that part is a claim, not a finding. The company says it saw no further attacker activity as of Friday and will publish a full account this week.

DoIf you expose an MCP server that can act on customer accounts, check that every tool call is limited to the signed-in user's own resources, and look at the logs for bursts of calls only a script could make.

Sources: The Record
CVSS 7.7CVE-2026-88968Claude Code

Claude Code before 2.1.251 could be tricked into writing files outside the project on macOS

The advisory says a race in the Edit tool let code running in Claude Code's Bash sandbox swap a folder for a symlink after the safety check, so the Edit tool wrote to a file outside the workspace. It needs attacker code to already run in the sandbox, for example from a malicious repository or dependency script. Not reported as exploited. Update to 2.1.251 or later.

AI attack

One attacker used AI agents to break into emergency services data in Taiwan

Acronis researchers, quoted by The Hacker News, say a single person in Taiwan pointed AI agents at hundreds of organizations in at least 11 countries and got data or access at about 10. The attacker mostly used local models with the safety training removed, because commercial models refused to help. The researchers found his server with more than 90,000 files. Acronis is the vendor that did the research.
