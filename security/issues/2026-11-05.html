CVSS 9.8CVE-2026-122006GHSA-f3w6-w445-fwh9Ruby on Rails

A crafted image upload can read secret keys from a Rails server

When a Rails app attaches an upload, Active Storage can hand the file to ImageMagick for analysis. ImageMagick picks how to read a file from its contents, and some formats act on other files named inside the image. An uploaded SVG reaches a scripting format that can read and write files on the server. Apps using the Disk storage service can lose any file they can read, including secret_key_base and credentials for other systems. Rails says one attack chain was reported and it does not assume that is the only one.

An app is affected only if it uses ImageMagick for Active Storage (config.active_storage.variant_processor = :mini_magick, the default on load_defaults 6.1 or earlier), its ImageMagick security policy does not block those formats, and it accepts uploads from untrusted users. Rails says the policies Debian and Ubuntu ship do not block them. The advisory does not say whether attacks are happening. Rails series older than 8.0 get no fix.

DoUpgrade to Rails 8.1.4.1 or 8.0.5.2, check which processor config.active_storage.variant_processor selects, and rotate secret_key_base if an unpatched app ever accepted public uploads.

Sources: The Hacker News · GitHub advisory · NVD
CVSS 7.7CVE-2026-109518Debian & Ubuntu

An APT flaw lets a tampered download run code as root

Someone who can change the HTTP traffic between a server and its package mirror, such as a bad mirror or proxy, can make APT retry a download and swap in their own unverified package. The package then installs as root. It needs retries turned on, which is the default from Debian 12 and Ubuntu 22.04, and older releases are exposed if scripts set Acquire::Retries. No attacks have been reported.

DoRun apt update and upgrade apt on your build and web servers. Ubuntu 24.04 LTS gets 2.8.4ubuntu0.1 and 22.04 LTS gets 2.4.15ubuntu0.1.

Sources: Debian · The Hacker News · NVD
CVSS 9.8CVE-2026-100109Plugin

Security For WooCommerce lets anyone create an administrator

Versions 1.0.10 through 1.0.16 create user accounts through an action that visitors without an account can call, and the caller chooses the new account's role. That means a visitor can make themselves an administrator and take over the site. The record was published this morning and NVD has not finished analyzing it.

DoCheck whether the plugin is installed. If it is, update past 1.0.16 once a fixed release appears; until then deactivate it, and review the Users screen for administrators you do not recognize.

Sources: NVD

CVSS 8.2CVE-2026-93389Plugin

LiteSpeed Cache can show one shopper's checkout details to the next visitor

In versions up to 7.9.1 with the default Cache REST setting, WooCommerce cart and checkout responses are stored as public cache entries without being tied to the shopper's session. A later visitor with no cookie can then read someone else's billing and shipping details. NVD has not finished analyzing the record.

DoUpdate LiteSpeed Cache past 7.9.1 when a fixed release is out. Until then, turn off the Cache REST setting on WooCommerce stores and purge the cache.

Sources: NVD
CVSS 9.1CVE-2026-122220Plugin

WPO365 | LOGIN accepts the same sign-in message twice

Before version 45.2, the plugin's check that stops a captured Microsoft sign-in message from being reused never actually saves the message ID. Someone who captures a valid signed message can replay it during its validity window and log in as that user, administrators included, without the duplicate check ever firing.

DoUpdate WPO365 | LOGIN to 45.2 or newer.

Sources: NVD
CVSS 9.8CVE-2026-119481CVE-2026-65555Plugins

JetFormBuilder and Uncanny Toolkit for LearnDash both list privilege escalation bugs

NVD lists an incorrect privilege assignment flaw in JetFormBuilder through 3.6.7.1 and in Uncanny Toolkit for LearnDash through 3.8.2, both scored 9.8. The records say nothing about how an attacker gets in or which release fixes it.

DoCheck each plugin's changelog and update to the newest version, and review administrator accounts on sites that run either one.

ExploitedCVSS 5.5CVE-2024-27834Supply chain

A hijacked analytics script served iPhone and Android exploits to visitors

French firm Sekoia says a campaign it calls Poisoned Source, presumed to be run by the Russia-linked group APT29, injected code into Plerdy SEO Tracker's script (a.plerdy.com/public/js/click/main.js) between August 27 and September 3. The same loader was also planted on compromised websites and lookalike domains. It profiles each visitor's device and serves an iOS or Android exploit chain that steals cookies and, on Android, Wi-Fi passwords. Sekoia thinks specific people were the targets, since several sites draw defense and policy audiences.

CISA added one bug in the iOS chain, CVE-2024-27834, to its exploited list on November 4. Apple fixed it in May 2024, so the exposure is phones that are not updated, plus any site that loads third-party scripts it cannot vouch for.

DoIf your sites load Plerdy, search your pages and logs for that script path and take it out until the vendor confirms it is clean. Audit third-party script tags generally, and tell staff to update iOS (the fix shipped in iOS 17.5 and 16.7.8).

Sources: The Hacker News · CISA KEV · NVD
HostingDreamHost

DreamHost says attackers stole FTP and SFTP logins from its File Manager

An attacker exploited a flaw on the server behind files.dreamhost.com and collected FTP and SFTP usernames and passwords from people who used it between about August and October 23. DreamHost found no sign that control panel logins or payment data were reached and has reset affected passwords. It advises checking site files for unauthorized changes and reviewing webmail forwarding rules.

HostingVercel

Vercel starts tying logins to the device so stolen cookies stop working

Vercel is gradually rolling out Device Bound Session Credentials for vercel.com logins, which keep a signing key in the computer's TPM so a stolen session cookie cannot be replayed elsewhere. It works in Chrome on macOS and Windows. The Vercel CLI gets a similar protection called DPoP.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

AI agentsCodexPrompt injection

A free Codex jailbreak kit rewrites the agent's instructions to show ads

Check Point Research found a bundle called Haiou that edits Codex's configuration so common greetings trigger an advertisement for a paid, OpenAI-compatible gateway. It does this through natural-language instructions rather than an executable, which is why researchers named it "prompt adware." It also installs penetration-testing skills. Check Point has no strong evidence of stolen tokens but calls such resold gateways suspect.

DoRead the global instruction files your coding agents load, such as AGENTS.md, and remove anything you did not write.

Sources: The Hacker News
AI platformsStolen API keys

Attackers are breaching developer platforms to steal AI access keys

SecurityWeek counts at least a dozen AI developer platforms hit in the past month, including Northflank, Trigger.dev, Railway and Zeabur, with intruders mostly after stored customer secrets. Wiz ties the surge to resale demand for stolen LLM keys, and says several attackers used the same compromised keys. Chainstack and WorkOS disclosed attacks that used an open source AI penetration testing framework to move faster.

DoRotate any AI provider keys stored in hosting platforms or CI, give each its own spending limit, and watch usage for spikes.

Sources: SecurityWeek
AI-found bugsLinuxVendor claim

OpenAI says an AI pipeline built 948 Linux root exploits in 30 hours

OpenAI reports its unreleased cyber model reproduced 1,724 kernel bugs and produced 948 local privilege escalation exploits for about $1.2 million in API credits. These are OpenAI's own figures about its own system, and the bugs go to maintainers after human review. The takeaway for web teams is that a local foothold on a shared server gets easier to turn into root, so kernel updates matter more.

Worth readingSupply chain

Supply chain attacks now hide in editor and agent config files

StepSecurity describes a June commit that changed no source code but added a .claude/settings.json startup hook and a .vscode/tasks.json task, so a credential stealer ran when a developer opened the repository in Claude Code, Gemini CLI, Cursor or VS Code. The post comes with a product launch, but the pattern is worth a manual look at your own repositories.
