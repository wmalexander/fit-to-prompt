CVSS 9.8 (v3.1)CVE-2026-135202WordPressBackdoored releases

Six WP connect plugins were backdoored through a hijacked developer account

Wordfence says a compromised developer account was used to push a remote-control backdoor into six plugins: Air WP Sync, WP Sync for Notion, Orders Sync to Airtable for WooCommerce, Add-On for Contact Form 7 to Notion, Add-On for Contact Form 7 to Airtable, and Add-on Brevo for Gravity Forms. According to the NVD record, the bad releases phone home to a server at tascredit-pay.com, run whatever PHP code it sends back, and can read or delete files, dump the users table and drop a web shell. Wordfence reports that WordPress.org's release hold stopped the releases before they reached sites, so most installs may be clean. I could only read Wordfence's summary, not the full post, so confirm that against their write-up. NVD marks the plugins closed with no patched versions, and its record has not been fully reviewed yet.

DoSearch every site for these six plugins. If one is installed, uninstall it, run a full malware scan, and check for unknown files in the uploads folder and for blocked or unexpected requests to tascredit-pay.com.

Sources: Wordfence · NVD
ExploitedCVSS 9.8 (v3.1)CVE-2026-133968Python

MONAI Label lets anyone write files to the server and gain control

CISA added this to its exploited list on November 23. A crafted request to the image upload endpoint can write files outside the intended folder, and one real attack used that to plant a reverse shell that ran as root. MONAI Label is an open-source medical imaging tool, so this matters most to university and hospital teams that run it. Versions before 0.8.6 are affected, and the federal due date is November 26.

DoUpdate MONAI Label to 0.8.6 or later, and keep it off the open internet until you have.

Sources: The Hacker News · NVD
ExploitedCVSS 9.3 (v4.0)CVE-2026-131914ASP.NETNo fix

An old ASP.NET anti-forgery add-on lets strangers run code on IIS

Idunno.AntiCsrf, a WebForms add-on last updated in 2008, trusts form data it should check first. One request with no login can run code on the web server, and Google's Mandiant says it has seen this used in real attacks. The project is abandoned, so no patch is coming. Versions 0.9.1.0 and 0.9.1 Beta are affected.

DoSearch your Web.config files and bin/ folders for Idunno.AntiCsrf, replace it with System.Web.Helpers.AntiForgery or ASP.NET Core antiforgery, and rotate the secrets in Web.config if you find signs of attack.

Sources: The Hacker News · NVD

CVSS 8.7 (v4.0)CVE-2026-135470WordPressNo attacks reported

WPC Product Options for WooCommerce lets shoppers name their own price

Versions before 4.0.9 accept a price sent from the browser, so a visitor with no account can submit a negative option price and check out at zero or any amount they choose. I could not confirm the plugin's install count.

DoUpdate WPC Product Options for WooCommerce to 4.0.9, and review recent orders for odd totals.

Sources: NVD
CVSS 8.7 (v4.0)CVE-2026-135446WordPressNo attacks reported

Bold pagos en linea can be tricked into marking unpaid orders as paid

Versions before 3.5.1 check payment notifications in a way an outsider can fake: a notification whose reference starts with "test" is signed with an empty key, which marks any unpaid WooCommerce order as paid. I could not confirm the plugin's install count.

DoUpdate Bold pagos en linea to 3.5.1, and compare recent "paid" orders against your payment dashboard.

Sources: NVD

ExploitedCVSS 9.8 (v3.1)CVE-2026-133469Node.js

Xen Orchestra can be logged into with an empty token

Xen Orchestra, a Node.js tool for managing XCP-ng and XenServer hosts, accepts a cookie that holds an empty object instead of a real token and signs the visitor in as the owner of the first saved token. The maintainers say it is being exploited. Versions before 6.9.2 and 6.10.1 are affected.

DoUpdate to 6.9.2 or 6.10.1, keep the web interface off the public internet, and revoke the saved login tokens if you cannot rule out a visit.

Sources: GitHub advisory · NVD

Chrome 158 fixes a critical bug that could escape the browser sandbox

The only security fix in this release is rated Critical by Chromium. A crafted web page could potentially run code outside the sandbox. Google lists no attacks and says it found the bug itself. Windows and Mac get 158.0.8127.88 or .89, and Linux gets .88, rolling out over the coming days.

DoUpdate Chrome to 158.0.8127.88 or later and restart it. Check for the matching update in other Chromium-based browsers.

Supply chainNuGet

13 fake NuGet packages hide inside job-interview coding tests

Socket found a campaign that hands .NET developers a "home assessment" project. Building or running it pulls files from GitHub, side-loads a malicious DLL or runs a downloaded program. It began on npm in July. One package, WinUI.Button 1.0.0, was still listed on NuGet when Socket wrote. Open take-home projects from recruiters in a throwaway virtual machine, not on your work machine.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

AI-assisted attacksCloud

AI attack tools are now behind a wave of cloud break-ins

Wiz Research says attacks run by AI agent frameworks such as ARTEX, Cairn and CyberStrikeAI have grown quickly, with twenty more incidents disclosed since its late-October warning. These tools are noisy: they spray passwords, create test accounts and label their own work as "pentest" or "recon", and they rotate through residential proxies, so blocking by IP does little. Wiz's report of 3x more incident-response requests is about its own customers. Watch for fast bursts of failed logins, sign-ups and password resets.

AI-found zero-dayExploited

AI agents found and used the MONAI Label bug in about 11 minutes

Amazon's security chief says a suspected China-linked operator pointed Cairn at a list of university servers with the goal "obtain shell access." The agents found the MONAI Label flaw above, planted a reverse shell and ran as root, with the operator not choosing each step. Patch speed is now measured in minutes.

Wordfence argues that the WordPress threat landscape changed drastically this year and expects the pace to continue in 2027, because researchers and attackers both use AI coding agents to find vulnerabilities faster.
