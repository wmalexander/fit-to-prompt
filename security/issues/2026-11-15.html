Patch now

Confirmed exploited or critical and easy to reach

No NVD score yetCVE-2026-127048WordPress

Custom Block Builder before 3.0.0 lets any visitor run PHP code on the site

The plugin's permission checks on its REST routes return a value that WordPress reads as "allowed," so a request with no login can use them. NVD says this lets an unauthenticated visitor run arbitrary PHP on the server. NVD has not scored it yet, and I did not find a report of exploitation.

DoUpdate Custom Block Builder to 3.0.0 or later, or deactivate it until you can.

Sources: WPScan · NVD
CVSS 9.8 v3.1CVE-2026-120522WordPress

Cloud Storage Manager for Fluent Forms lets a stranger write a file anywhere the site can

Two REST endpoints in the add-on have no permission check, and the Google Drive download code builds a file path from a name the remote side supplies. NVD says an attacker can use that to save a file outside the downloads folder, and a PHP file in a public folder means code running on the server. Versions up to 1.2.0 are affected.

DoUpdate to the current release (1.2.9 on WordPress.org today) and check the uploads and plugin folders for PHP files you do not recognize.

Sources: Wordfence · WordPress.org · NVD
CVSS 9.8 v3.1CVE-2026-19907WordPress

Shipo 1.6 to 1.8.0 trusts a login cookie without checking it, so anyone can act as an admin

The plugin reads the username out of the login cookie and signs that user in without checking the cookie's signature. Per NVD, an attacker who knows a username, including an administrator's, can use the REST API to act as that person and create a new administrator account.

DoUpdate Shipo to the current release (1.8.4 on WordPress.org today), then review the administrator list for accounts you did not create.

Sources: Wordfence · WordPress.org · NVD
No NVD score yetCVE-2026-126697WordPress

Quick Page/Post Redirect shipped with a hidden updater that pushed a backdoored build

Per NVD, version 5.2.1 on WordPress.org carried an update checker that polled the author's own server, and in March 2021 that server delivered a changed 5.2.3 that added spam and a remote-code path. WordPress.org shows the plugin closed for a security issue since April 14, 2026. Treat any site that ran the tampered build as compromised.

DoRemove the plugin. If you must keep it, install the clean 5.2.4, delete any updater/ folder, and search your logs and plugin files for anadnet.com.

Sources: WPScan · WordPress.org · NVD
02

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 7.1 v3.1CVE-2026-124969WordPress

Optimole 4.2.19 and earlier can be tricked into deleting files, including wp-config.php

Per NVD, the image plugin does not check a file path in its rename feature. Exploiting it needs PEAR's Archive_Tar library on the server, which NVD says is common in official WordPress Docker images, and an administrator who uses the plugin's Rename control after the attacker plants a payload in a comment. So it is not a one-step attack.

DoUpdate Optimole to 4.2.20 or later, and avoid the Rename control on older versions.

Sources: Plugin code, 4.2.20 · WordPress.org · NVD
No NVD score yetCVE-2026-117487CVE-2026-117490WordPress theme

Flatsome before 3.20.13 leaks unpublished posts to strangers and lets contributors publish

Per NVD, an AJAX action in the Flatsome theme has no permission check, so a visitor can read draft and pending posts by ID. A second bug lets users as low as Contributor publish their own content and change its post type, for example to a product. NVD has not scored either one.

DoUpdate Flatsome to 3.20.13 or later through the theme's own update channel.

Sources: NVD 117487 · NVD 117490

Node.js, React & Apache watch

The runtime, the front-end framework and the servers under a lot of the web

CVSS 8.2 v4.0CVE-2026-129319npmNode.js

create-ecdh 4.0.4 and earlier skips a key check that can leak a private key

Bundlers pull this package in to stand in for Node's built-in ECDH when the native one is missing. Per NVD, it did not check that a peer's public key is on the curve, so someone who can send keys to a service that reuses one private key can slowly recover that key. Version 4.0.5 was published to npm on November 14. NVD has not finished its analysis.

DoRun npm ls create-ecdh, and update to 4.0.5 where it shows up.

Sources: npm · NVD
Apache httpdNode.jsReact

Nothing new from Apache, Node.js or React today, and this week's fixes are still open

None of today's feeds posted a new release. Still open from this week: Apache httpd 2.4.71 (or Protocols http/1.1 as a stopgap), Node.js 22.23.5, 24.22.3 and 26.13.1, and React Server Components packages 19.0.9, 19.1.10, 19.2.9 and 19.3.1. Confirm your servers and lockfiles use them.

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

ExploitedCVSS 8.6 v3.1CVE-2026-114713UnrealIRCd

Attackers are exploiting UnrealIRCd, the chat server, and CISA wants it fixed by November 16

This one is not a web server, but teams that run IRC for communities or support often forget it. UnrealIRCd 6.0.0 before 6.2.7.1 does not escape a message tag, so any user on a network with two or more linked servers can inject server-to-server commands. The maintainer says attacks began the day after the November 7 hotfix and that AI helped find the bugs fixed in 6.2.7.1. CISA added it to KEV on November 13.

DoUpdate UnrealIRCd to 6.2.7.1, or deploy the maintainer's spamfilter workaround if you cannot restart yet.

Sources: The Hacker News · CISA KEV · NVD
PyPI

PyPI's project pages now show a Security tab with where each release was built

PyPI says the redesign is live. The new tab shows each release's provenance state, meaning whether every file carries an attestation tying it to a Trusted Publisher or a source commit. It is a quick check before you add an unfamiliar Python package, though a missing attestation alone does not mean a package is bad.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

Supply chainClaude CodeCursor

A stolen vendor key led to a trojan Claude Code extension on Cursor's marketplace

Cursor's incident report says an attacker got an access key Cursor had issued to Fireworks AI, which Fireworks exposed, and used it to copy a storage bucket of older coding-agent traces. Some traces held credentials nobody had removed, and those opened Cursor's other tools. On October 29 the attacker placed fake copies of Anthropic's Claude Code extension, versions 2.1.312 and 2.1.313, in the cache behind Cursor's extension marketplace. They were up about 11 hours, and at most 5,000 users may have received them. Cursor says Anthropic's own extension and Open VSX were not changed. BleepingComputer reports the fake extension tried to install an attacker's SSH key, though coding errors likely stopped it on many Windows and Mac machines. Cursor says it has seen no new malicious activity since November 1, and that Privacy Mode users were not affected.

DoIf anyone on your team updated Claude Code inside Cursor on October 29, check for those two versions and look for an unfamiliar key in ~/.ssh/authorized_keys, then follow Cursor's remediation steps. Also rotate any key you ever pasted into an agent session or sent to a vendor's support team.

Sources: Cursor incident report · BleepingComputer · The Hacker News
Worth reading

Project Zero will publish bug details 90 days after reporting, then 60, then 30

Google's team says AI has cut the time attackers need to find and exploit a bug, and to work one out from a patch, so the old "90 plus 30 days" rule no longer fits. The new policy is "Full 90" now, "Full 60" from February 2, 2027 and "Full 30" from January 3, 2028. Actively exploited bugs follow Google's separate policy. Its point is that the gap between a fix shipping and your update landing matters more now.

Credential theft

The Cursor breach is part of a wave Wiz calls "Black October"

BleepingComputer says attackers have targeted AI developer platforms to steal credentials, including at Railway, Northflank, Lightning AI, OpenCode and Warp. It reports about $740,000 in fraudulent AI charges at Railway. The stolen credentials were mostly ones that give access to AI models, so give those keys expiry dates and spending limits.
