PostgreSQL fixes a 22-year-old bug that lets a database user run code on the server

PostgreSQL's November 12 release fixes 52 security flaws. The worst known one, CVE-2026-6460, comes from a type change that leaves old values read as the wrong type. A database user who can create objects can use it to run code with the rights of the operating system account that runs PostgreSQL. All versions before 18.7, 17.12, 16.16, 15.20 and 14.25 are affected. The project and CISA's record report no attacks so far, but a researcher published a write-up that shows a working crash and a memory leak on 18.6 and withholds the final step. A second bug, CVE-2026-116322, needs no login: an anonymous client can restart a PostgreSQL 18 server before 18.7. Older branches are not affected by that one. Several client tools also got fixes, including pg_restore and psql, which can run code from a crafted archive or a compromised source server. PostgreSQL 14 reaches end of life with 14.25.

DoUpdate the server to 18.7, 17.12, 16.16, 15.20 or 14.25, and rebuild or update every C-language extension at the same time, because extensions built against older releases may not be protected. Restart PostgreSQL right after updating if it runs outside its package's service unit, as it does under Patroni. Update pg_dump, pg_restore and psql on every machine that runs them. Plan a move off 14, and do not turn off the new composite_type_mismatch check.

Sources: The Hacker News · PostgreSQL security page · NVD 6460 · NVD 116322
CVSS 9.4 v4.0CVE-2026-128049CVSS 9.2 v4.0CVE-2026-128046OpenMage

OpenMage (Magento LTS) lets a stranger upload a PHP-type file, and a second bug can hijack an admin's session

Per NVD, the file blocklist in OpenMage 20.17.0 before 20.18.2 and 21.0.0-beta1 before 21.0.0-beta3 leaves out phar, php8 and phps. An unauthenticated visitor can upload a .phar file through a product's File custom option and request it directly. That runs code on servers that treat .phar as PHP and serve that folder. CVE-2026-128049 is a cross-site request forgery bug in the OAuth confirm pages. An attacker who holds OAuth consumer credentials can trick a logged-in admin or customer into approving the attacker's token. No attacks are reported in the sources I read.

DoUpdate to 20.18.2, or 21.0.0-beta3 if you run the beta line. Until then, make sure your web server does not run .phar files from media/.

Sources: NVD 128046 · NVD 128049
CVSS 9.2 v4.0CVE-2026-128014CVSS 9.1 v4.0CVE-2026-128023FrankenPHP

FrankenPHP before 1.13.0 can be fooled about who is logged in, and its static builds can crash on bad data

Per NVD, FrankenPHP before 1.13.0 lets a visitor spoof trusted headers. PHP rewrites dots in header names to underscores, so a header such as X.Forwarded.For lands in the same server variable as the real one. That can fake a user identity, a client IP address or the scheme. Separately, standalone static binaries 1.8.0 before 1.13.2 bundle a Brotli decoder with an out-of-bounds write. An unauthenticated visitor can crash the whole process by sending data to an app that passes it to brotli_uncompress_add(), and NVD says code execution or a memory leak may be possible.

DoUpdate FrankenPHP to 1.13.2 or later, including any Docker images and static binaries you ship. Check whether your app trusts X-Forwarded-For or similar headers from PHP's server variables, and strip them at the proxy.

Sources: NVD 128023 · NVD 128014

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 10.0 v3.1CVE-2026-124822WordPress

Easy DragDrop File Uploader before 1.1.10 lets strangers delete any file, including wp-config.php

Per NVD, the plugin does not check a path it is given before deleting it, so an unauthenticated visitor can delete files and folders on the server. Deleting wp-config.php can put a site back into install mode. Update to 1.1.10 or later.

CVSS 9.8 v3.1CVE-2026-126119WordPress

Streamit before 1.3.10 lets strangers run any PHP function, which can create an admin account

Per NVD, one unauthenticated AJAX route runs a PHP function chosen by the visitor with arguments the visitor supplies, with no permission or nonce check. NVD names creating an administrator and running code as results. Update to 1.3.10 or later.

CVSS 9.8 v3.1CVE-2026-119077WordPress

ELEX HelpDesk plugin through 3.3.9 lets strangers run code through a ticket form

Per NVD, the plugin unserializes a form field without a class allowlist, and the only guard is a nonce printed on any page that carries the [wsdesk_support] shortcode. NVD lists all versions through 3.3.9 and I found no fixed version, so deactivate it or remove the shortcode pages until the author ships one.

CVSS 9.8 v3.1CVE-2026-125055WordPress

Chatterbug Forms through 1.0.2 accepts PHP uploads from anyone

Per NVD, when a form field has no file restriction, the plugin accepts any extension, including .php, and a nonce on every public form page lets a visitor use it. NVD lists versions through 1.0.2 and I found no fixed version, so deactivate it until one appears.

CVSS 9.8 v3.1CVE-2026-126173WordPress

AutomatorWP Pro through 1.4.4 can let a stranger reset an admin's password, but only with one setup

Per NVD, this affects the Webhooks add-on only when an automation pairs a Receive Webhook trigger with an Update User action whose User ID is blank and whose password field uses the webhook password tag. Check your automations for that pattern and update past 1.4.4 when a fix is out.

CVSS 9.2 v4.0CVE-2026-124020CVSS 9.2 v4.0CVE-2026-124021Control Web Panel

Control Web Panel before 1.30.6 has a password-reset bug that leads to commands on the server

Per NVD, a forged Host header poisons the password-reset link, and a mail scanner that opens the link leaks the token. A second bug lets someone holding that token add cron commands and read account lists with password hashes. Update to 1.30.6 and keep the panel off the open internet.

Apache httpd

Apache's HTTP/2 code-running bug is still open: upgrade to 2.4.71 or turn HTTP/2 off

Nothing new landed today, so this carries forward from earlier in the week. The critical HTTP/2 module bug affects Apache HTTP Server 2.4.55 to 2.4.70. Upgrade to 2.4.71, or set Protocols http/1.1 until you can. Updating WordPress does not fix it, because the bug is in the web server.

Node.jsReact

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

Active campaignnpm

A fake job interview ran malware through look-alike Tailwind packages that stayed on npm for months

JFrog exposed a fake company, AccuraSoftHire, whose take-home test loads a malicious copy of a Tailwind plugin when the CSS builds. StepSecurity checked the npm records and found that two of the packages, tailwind-lines-clamps and tailwind-lineclamp, were installable for about seven and five months until npm replaced them on November 13 and 12, with more than 4,000 downloads this year between them (mirrors and scanners included). Binance says its $6.34 billion theft began with a similar fake assignment. Search developer laptops for those package names and for .vscode/tasks.json files with "runOn": "folderOpen". Treat any machine that ran an interview assignment as compromised.

Takedown

Police seized Gootloader, CastleRAT and StealC servers, and 681 infected websites were cleaned up

Europol says Operation Endgame seized 235 servers and 257 domains and collected 6.4 million stolen credentials, which went to Have I Been Pwned. Gootloader spreads through hacked websites that show fake legal documents, so it is worth searching your own sites for unexpected pages. If your team uses Have I Been Pwned, check your domains this week.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

Active campaignAI agentsFBI

The FBI warns that the open-source AI hacking tool ARTEX is spreading even after its author pulled it

ARTEX lets AI agents plan and run a penetration test on their own. The FBI's Friday flash alert says some intrusions went from first targeting to privileged access in under three hours, and that forks, archived copies and a commercial version keep it available after the author removed it on October 8. Censys counted more than 1,600 exposed ARTEX consoles. Cloudflare says it has seen more than 50 similar tool families scanning its customers in three days, and daily requests from these tools are up 30 times since October 1. StepSecurity's review of the public reporting finds that the agents get in fastest with a credential left in the open: a secret in a public GitHub repository, or a development password that reached production. These are vendor and agency reports, and the attack counts come from their own telemetry.

DoScan your public and internal repositories, including git history, for secrets, and rotate every one you find, because deleting the file does not make a leaked secret safe. Replace long-lived cloud keys in CI with short-lived OIDC tokens, set an expiry on every personal access token, and make sure no internet-facing system accepts a development or default login.

Sources: The Record on the FBI alert · StepSecurity · Cloudflare
AI tools

OpenAI launches Daybreak Red Team, an AI agent that tests web apps, and Defense Factory, which drafts patches

OpenAI announced both on November 12. Red Team uses agents to investigate and confirm attack paths in web applications, and Defense Factory traces findings through your code and opens draft GitHub pull requests for engineers to review. Nothing deploys on its own. Red Team is early access and Defense Factory is a preview. This is a vendor announcement, and I have not tested either product.

Worth reading

Cloudflare's six-part plan for defending against AI penetration-testing tools

Cloudflare names rate limits and a WAF, anomaly detection, bot defense, identity-gated access for risky apps, schema validation and threat intelligence. It is vendor guidance and leans on its own products, but the list of what the tools target (partner portals, mobile backends, staging and legacy apps) is useful for an inventory.
