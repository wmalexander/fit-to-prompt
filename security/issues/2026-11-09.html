Confirmed exploited or critical and easy to reach

CVSS 8.1CVE-2026-123158OpenSSH

Attackers are trying very long passwords against OpenSSH on Alpine-style Linux

NVD says OpenSSH before 10.6p2 on Linux, when it uses musl libc without PAM, can accept any password between 256 and 1,024 characters for some accounts. Alpine Linux is the example NVD gives, so many container images are in scope. The SANS Internet Storm Center saw its honeypots receive a rising number of very long passwords from November 4, peaking at 713 on November 6 and falling to 51 on November 8, with the first real exploit attempt on November 5. Some of those long passwords came from buggy brute-force scripts, not exploits. Risky Business also reports exploitation in the wild. It is not in the CISA KEV catalog.

DoUpgrade OpenSSH to 10.6p2 or later on any Alpine or other musl-without-PAM host that accepts SSH from the internet, including base images you build on. Until then, limit SSH to known addresses.

Sources: SANS ISC · Risky Bulletin · NVD
ExploitedCVSS 7.5CVE-2026-19868SonicWall

CISA now sets a November 20 deadline for the SonicWall VPN login bypass

This is the SonicOS SSL VPN bug from yesterday's briefing, where a valid login for one sign-in method can skip SAML login and its two-step check. CISA lists it in the Known Exploited Vulnerabilities catalog (added November 6), and U.S. federal agencies must patch by November 20. SonicWall also fixed three other high-severity bugs: CVE-2026-107155 and CVE-2026-107154 (both 8.8, management interface) and CVE-2026-82308 (7.5, a VPN crash).

DoUpgrade to SonicOS 7.3.4-7013 or 8.2.3-8015 as listed in yesterday's briefing. SonicWall lists no workaround for the login bypass.

Sources: The Hacker News · NVD · CISA KEV catalog

CVSS 9.8CVE-2026-114432WordPress

Contact Form 7 before 6.2.4 lets strangers upload files, which can run code on some Apache servers

NVD says the plugin does not check the type or extension of files sent through a form file field, and its cleanup step leaves the file on disk. On a stock Debian or Ubuntu Apache setup that lists folder contents and runs .phar files as PHP, an attacker can find and run the uploaded file. On nginx, or Apache with .htaccess overrides on, the result is a file written to the uploads folder, which can still be served as active content. The WordPress.org plugin page lists 6.2.4.1 as the current release, updated October 29. NVD's analysis is still pending and I found no report of exploitation.

DoUpdate Contact Form 7 to 6.2.4 or later (6.2.4.1 is current) and look in the uploads folder for .phar, .php or other files you do not recognize.

Sources: WordPress.org plugin page · NVD
CVSS 9.8CVE-2026-110963WordPress

Userplace, up to 1.2.0, lets anyone create an administrator account

An AJAX action skips its permission check and the nonce that guards it is shown publicly, so a visitor can create an admin account or change site options. NVD lists no fixed version, I could not find the plugin in the WordPress.org directory, and the only source is NVD. Not reported as exploited. Deactivate and remove it, then check your user list for admins you do not recognize.

CVSS 9.1CVE-2026-119506WordPress

Frontend Admin by DynamiApps, up to 3.30.1, has a privilege escalation bug

NVD gives few details beyond incorrect privilege assignment, and its analysis is deferred. The WordPress.org page lists 3.30.2 as current, updated November 1, but NVD does not say which release fixes it, so read the changelog. Not reported as exploited. Update to 3.30.2 or later.

CVSS 9.6CVE-2026-109900WordPress

Melapress Role Editor, up to 1.3.0, has a privilege escalation bug

NVD lists incorrect privilege assignment and nothing more, and its analysis is deferred. The WordPress.org page lists 1.4.0 as current, updated October 30, but NVD does not say which release fixes it. Not reported as exploited. Update to 1.4.0 or later and review who holds the administrator role.

CVSS 8.7CVE-2026-124430CVE-2026-124427Craft CMS

Craft CMS 5.x before 5.11.2 has a code execution bug for logged-in staff and a data leak

CVE-2026-124430 (8.7, versions 5.10.0 up to 5.11.2) lets a control panel user who is not an administrator run operating system commands. CVE-2026-124427 (9.3, versions 5.0.0 up to 5.11.2) lets anonymous GraphQL visitors read entries from sections that should be hidden. The only source is NVD, and neither is reported as exploited. Upgrade to 5.11.2.

Web stack & supply chain

Supply chainnpm

A poisoned npm release, @ethersphere/bee-js 13.3.0, steals crypto wallet data when you install it

StepSecurity says version 13.3.0 was published to npm on November 9 at 00:09 UTC. It moves a script to run at install time, downloads JavaScript from a server the attacker controls, and runs it. The payload goes after Swarm Desktop wallet files and tries to stay on the machine on Linux, macOS and Windows. The release carries valid build provenance because the attacker pushed the code to the project's own release branch under a bot identity, so a provenance badge alone would not have caught it. StepSecurity is the vendor that found it, and it has not said how the account was reached.

DoSearch your lockfiles and CI logs for @ethersphere/bee-js 13.3.0 and pin 13.2.0. If 13.3.0 was installed with install scripts enabled, treat that machine as compromised and rotate its secrets, because removing the package does not remove the persistence.

Sources: StepSecurity

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

AICryptography

Google DeepMind says its AI agents made attacks on old 1024-bit RSA keys cheaper

Working with outside cryptographers, DeepMind reports that AI agents helped cut the cost of forging signatures on a 1024-bit RSA key by 3.5 times in a test (391 CPU core-years versus 1,380 in an earlier study), and sketched a method that makes factoring each extra key of that size about 30 times cheaper on average, which has not been built. The forgery needs about four billion signing requests and does not work on devices that hash messages internally. DeepMind says 2048-bit and larger keys remain secure. These figures come from the vendor about its own research.

DoSearch for RSA keys under 2048 bits in your TLS certificates, JWT signing keys and code-signing setups, and replace any you find.

Sources: SecurityWeek
