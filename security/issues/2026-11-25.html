Attackers are abusing Drupal's installer to take over live sites

Drupal core ships an installer that sets up new sites. Under certain conditions an unauthenticated visitor can use it to reinstall Drupal, which can hand them the site or let them run code. Drupal says it was exploited on live sites as early as Nov 19, one day after the Nov 18 patch, and raised the rating to "highly critical" afterward. CISA added it to its Known Exploited Vulnerabilities list on Nov 24 with a Nov 27 deadline for federal agencies. The NVD has no record for this one yet, so no CVE number or CVSS score is printed here. Anthropic's open source scanner is credited with finding it.

DoUpdate to Drupal 11.4.13, 11.3.22 or 10.6.22 today. End-of-life branches get no fix, so move them. Also make settings.php read-only for the web server and block the installer path, which Drupal says closes some of the attack routes.

Sources: Drupal advisory SA-CORE-2026-018 · SecurityWeek · CISA KEV catalog
ExploitedCVSS 7.1 (v4.0)CVE-2026-132224Optimizely

Optimizely's signup flow let attackers plant code in the script your site loads

A flaw in how Optimizely Web Experimentation handled account signup could leave attacker-controlled code in the Project JavaScript field of assets served from cdn.optimizely.com. Any site that loads that script runs whatever is in it. NVD says versions before 2026-11-17 are affected, and CISA added it to its exploited list on Nov 24. The fix is on the vendor side, so there is no package to update.

DoIf your pages load an Optimizely snippet, open your project's JavaScript and look for code you did not write, and review any Optimizely accounts created recently.

Sources: NVD · CISA KEV catalog

WHMCS shopping cart bug lets strangers read customer data

WHMCS is the billing system many hosting companies run. A SQL injection in its shopping cart lets anyone who can load the cart read client records and admin password hashes, with no login. Two more flaws, including CVE-2026-82979 (7.1, v4.0), need a logged-in client. WHMCS has not reported attacks. Self-hosted installs must update themselves; WHMCS Cloud updates automatically.

DoUpdate to WHMCS 9.0.10, 8.13.8 or 9.1.2. Installs on 8.0 to 8.12 have no fix and need to upgrade to a supported release.

Sources: The Hacker News · NVD
CVSS 9.4 (v4.0)CVE-2026-129393Joomla

Joomla fixes a remote code execution bug in media fields

Joomla core versions 4.0.0 to 5.4.10 and 6.0.0 to 6.2.0 let crafted media field parameters change the form definition and run code. Joomla's Nov 24 release is 5.4.11 and 6.2.1; The advisory text was not readable at build time and NVD's entry is still deferred, so confirm in the Joomla security centre that those versions cover this bug.

Wordfence analyzed a campaign that installs a fake plugin whose titles, folders, functions and REST namespaces are all generated from a prefix, a tech word and a suffix, such as "trijavascriptly" and "ultravueal". This summary comes from Wordfence's feed excerpt, not the full post. Look for plugins you never installed.

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

Supply chainGitHub Actions

Pinning a GitHub Action to a SHA does not prove who wrote it

The Hacker News, in a piece promoting a webinar, says attackers used forks to get code that looks like it came from GitHub's official checkout action into pinned workflows. It names the March 2026 Trivy hijack and the May actions-cool/issues-helper attack. A SHA can be a commit from a fork. Check that each pinned SHA exists in the action's own repository, not just that it is pinned.

AI × security

AI-driven attacksWeb shells

Unit 42: in 10+ AI-agent campaigns, the way in was always a vulnerable web app

Palo Alto's Unit 42 tracked more than 10 campaigns between July and September 2026 where attackers used autonomous AI agents. Every one started with a web shell on a vulnerable web application. The agents ran hundreds of commands in minutes but left obvious marks, such as structured output and reasoning comments inside shell scripts. This is the vendor's own research.

CVSS 10.0 (v3.1)CVE-2026-59726npmMCP

ruflo's default Docker setup exposes an MCP bridge with no login

Ruflo, a harness for Claude Code and Codex, exposed its MCP bridge endpoints in the default docker-compose setup without authentication. An outsider could run terminal commands in the container, read provider API keys and tamper with its stored learning data.

DoUpdate ruflo to 3.16.3 or later, and rotate any API keys it held if the bridge was reachable from outside.

Sources: GitHub advisory · NVD
AI-assisted attack

GreyNoise: AI tooling used against Check Point management servers

GreyNoise says one actor used agentic tools to find and exploit targets across at least 22 organizations since early October, with hands-on activity too. It is a security appliance story, but the same speed applies to any exposed web service.

Worth readingLinux

Shirudo: OpenAI and Cisco's open source tool for blocking exploits before you patch

Shirudo uses Linux eBPF to load temporary "shields" that block a vulnerable code path without restarting services. AI agents can help write and test shields, but a human approves deployment. It is a stopgap while you roll out patches, not a replacement for them.
