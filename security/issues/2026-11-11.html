CVSS 9.5 v4.0CVE-2026-126187React

React Server Components has a critical bug that lets strangers run code on the server

The React team says crafted requests aimed at frameworks that use React Server Components can run code on the server with no login. It affects react-server-dom-webpack, react-server-dom-parcel and react-server-dom-turbopack in versions 19.0.0 through 19.0.8, 19.1.0 through 19.1.9, 19.2.0 through 19.2.8, and 19.3.0. React says it only applies in extremely rare cases, where a response carries several typed arrays and a value the attacker controls. An app with no server-side React, or no framework or bundler plugin that supports Server Components, is not affected. I found no report of attacks in the wild, and the bug is not in the CISA catalog.

DoRun npm ls react-server-dom-webpack react-server-dom-parcel react-server-dom-turbopack in each app and any framework starter it came from. Upgrade to 19.0.9, 19.1.10, 19.2.9 or 19.3.1, whichever matches your line. Next.js and other frameworks may bundle their own copy, so check their release notes too.

Sources: GitHub advisory · NVD
CVSS 9.8CVE-2026-126082Ruby on Rails

Rails apps that resize images with ImageMagick can leak secrets to strangers

NVD says Active Storage before 8.1.4.1 and 8.0.5.2 can let an unauthenticated attacker write files on the server, and read files too when attachments sit on the Disk service. Those files usually include secret_key_base and credentials for other systems. It applies to apps that process attachments with ImageMagick. I did not find a vendor advisory yet, so this rests on the NVD record, which is still marked "Received".

DoUpgrade Rails to 8.1.4.1 or 8.0.5.2. If an app was exposed, rotate secret_key_base and any credentials stored on the server.

Sources: NVD
Fixed in 2.56.1Git

Git fixes a bug where cloning a booby-trapped repository with submodules can run the attacker's code

An extremely long path in a repository can slip past Git's safety check, then get written to disk under a shorter name set to .git. That lets an attacker swap a submodule's .git file for a link to a folder of malicious hooks, which Git then runs. The Hacker News says the same releases fix five other flaws. The CVE number is not in NVD yet, so I am not printing it. GitHub has fixed github.com, and says GitHub Enterprise Server is fixed in 3.19.15, 3.20.11, 3.21.9 and 3.22.4. Git for Windows had no fixed build as of Tuesday evening.

DoInstall Git 2.56.1, or the fix for your line (2.50.2, 2.51.3, 2.52.1, 2.53.1, 2.54.1 or 2.55.1). Until then, do not recursively clone repositories you do not trust, and update CI images that ship their own Git.

Sources: The Hacker News

CVSS 9.8CVE-2026-89324WordPress

Basel Post Types plugin lets anyone forge a login

NVD says every version up to and including 1.18 has an authentication bypass. A coding slip makes the plugin always fall back to a fixed signing secret that is visible in the theme's source, so an attacker can build a valid login callback offline and send it to a public endpoint. The record does not list a fixed version and is marked "Deferred", and I found no report of attacks. Nothing else in the WordPress feeds met the bar today: Wordfence's 9.1.0 post is a product release, and the PHP and WordPress.org feeds were quiet.

DoIf you run Basel, which usually comes bundled with the Basel theme, check the plugin version. On 1.18 or earlier, deactivate it until the author ships a fix, and review recent new or changed administrator accounts.

Sources: NVD

Due todayNode.js

Node.js security releases are due today, and none were posted yet when I checked

The project says new 26.x, 24.x and 22.x releases land on or shortly after November 11, and the highest severity fixed is High. The latest release on the blog at 4:30 AM ET was 26.13.0 from October 28. Plan to upgrade the same day; End-of-Life lines are always affected.

CVSS 8.2CVE-2026-125117CVSS 7.5CVE-2026-125119Mongoose

Mongoose has two new bugs, one that overwrites built-in functions and one that quietly turns off query filtering

Per NVD, CVE-2026-125117 lets crafted keys such as toString make Mongoose write into shared built-in functions, which can break later queries on unrelated models. CVE-2026-125119 means the sanitizeFilter option set on the connection is never read, so an app that trusts it can still match accounts with a crafted password object. Both are fixed in 6.13.12, 7.8.13, 8.24.7 and 9.11.4. Neither is marked exploited. Yesterday's Mongoose bug was a different one.

DoUpgrade Mongoose to the fixed version for your line. Set sanitizeFilter on each query too, and cast request values to strings before using them in a filter.

Sources: Mongoose advisory · second advisory · NVD · NVD
CVSS 7.5CVE-2026-119191node-forge

node-forge can be made to burn CPU and memory on nested input

NVD says versions before 1.4.1 skip the depth limit when reading nested BIT STRING values, so a crafted certificate can cause heavy CPU and memory use. It matters if your server parses certificates or keys from strangers. Upgrade node-forge to 1.4.1 or later.

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

Exploited per vendorAuth bypassXen Orchestra

Attackers are using a cookie trick to log in as admin on Xen Orchestra

Vates says a crafted authenticationToken cookie makes Xen Orchestra treat an empty object as a valid token and sign the request in as the first token's owner, which leads to admin access and code running as root on managed hosts. Vates says it is seeing exploitation and lists indicators, including cron files named zz-ustar. There is no CVE yet (it is tracked as VSA-2026-062), and it is unclear whether it was a zero-day. This is infrastructure rather than web code, but many web teams run it.

DoUpgrade to Xen Orchestra 6.9.1 (stable) or 6.10.0 (latest). Keep it off the public internet, and if the indicators match, rotate every password and secret.

Sources: The Hacker News
ExploitedCVSS 8.8CVE-2026-125350Chrome

The Chrome zero-day from yesterday now has a CVE number, and a second serious Chrome bug was fixed with it

Yesterday's briefing covered the exploited Chrome XML bug without a number. It is now CVE-2026-125350, and CISA added it to its exploited list on November 10 with a November 24 deadline. NVD also lists CVE-2026-125347 (9.6, a file system permission bug that needs social engineering and could run code outside the sandbox) in the same Chrome 157.0.8103.50 release. That second one is not marked exploited.

DoIf Chrome and other Chromium browsers are not on 157.0.8103.50 or later, update and relaunch. That includes browsers embedded in test tools.

Sources: The Hacker News · NVD · NVD
BreachRailway

Railway says stolen customer AI keys led to about $740,000 in unauthorized charges

The hosting platform says an October breach let an attacker decrypt stored variables in at most 1.85% of workspaces, about 100,000, and the queries hunted for AI provider keys. Linked-account tokens for 1,852 users were also taken and have been reset. Railway also says it will pay the charges itself when an AI provider will not refund them. The figures are the company's own. Treat any key kept as a platform environment variable as exposed if you were a customer, and rotate it.

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

Exploited per vendorRCESGLang

A bug in the SGLang inference server let an attacker run code on NEAR AI's servers

NEAR AI says an attacker used a remote code execution flaw in SGLang on an inference server last Sunday, then reached a deprecated product and 18 AI agents on an older deployment. About 100 users' account details were downloaded, and two customers' API keys showed up in logs and were revoked. The privacy mode that runs inside a trusted execution environment did not help, since the vulnerable software ran inside it. The flaw has no CVE number yet. These details come from NEAR AI's own report.

DoIf you run SGLang, ask the project for the fixed release and keep the server off the open internet. Keep API keys out of logs.

Sources: The Hacker News
CVSS 8.8CVE-2026-113663AG2

AG2's "read-only" shell tool for agents can be tricked with a newline

NVD says the sandbox filter in AG2 and AutoGen skips newline characters, so a command that passes the allow-list can carry a second command that runs on the host. That undoes allowed=[...] and readonly=True. It is fixed in AG2 1.1.1 and AutoGen 0.14.1 or later.

DoUpgrade AG2 to 1.1.1 or later and AutoGen to a version past 0.14.1. Run agent shells in a container, not on the host.

Sources: GitHub advisory · NVD
