Patch now

Confirmed exploited or critical and easy to reach

ExploitedCVSS 8.1CVE-2026-119977WordPress

Attackers are probing WordPress sites for the core upgrade bug, and the federal deadline is today

WordPress core versions 4.7 through 7.1.3 use staging folders during a full core upgrade that attackers can guess and reach from the web. During that short window, an unauthenticated visitor can run code on the server. WordPress shipped 7.1.4 and matching releases for older branches on October 28. CISA added the bug to its exploited list on November 3 and gave federal agencies until today to patch, and Wordfence reports that attackers are actively probing for it. The Wordfence page itself could not be read by our tools today, so its details here come from its published summary.

DoUpdate to WordPress 7.1.4, or the matching security release for your branch, and check that every site on your server updated, not just the ones you manage by hand.

Sources: Wordfence · NVD · CISA KEV catalog
CVSS 8.1CVE-2026-123158OpenSSH lets anyone log in to some Alpine Linux accounts with one very long password

On Linux systems that use the musl C library without PAM, such as Alpine Linux, OpenWrt, Buildroot and Yocto, an attacker can send a password longer than 256 characters and get into accounts that should only accept keys. The server also needs at least one other account with a normal password. Debian, Ubuntu, Fedora and anything using PAM are not affected. No attacks had been reported when the articles were written, but the steps are public and take one connection. The researcher says he found it with AI agents, and the OpenSSH maintainer says quick AI rediscovery is why this fix shipped a day after he heard of it.

DoUpgrade to OpenSSH 10.6p2 (on Alpine, run apk upgrade openssh) and restart sshd, because the package upgrade alone does not replace the running process. If you cannot upgrade yet, set PasswordAuthentication no and restart sshd.

Sources: Alpine Linux advisory · BleepingComputer · SecurityWeek · NVD

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 9.8CVE-2026-107622Plugin

BuddyForms lets a logged-out visitor create content of the wrong type and gain more access

All BuddyForms versions up to and including 2.10.5 trust a post type sent by the visitor on public submission forms. That lets someone who is not logged in create objects they should not be able to, which can lead to privilege escalation. NVD has not finished its analysis, so treat the score as provisional.

DoUpdate BuddyForms to 2.10.6 or later, the current release on WordPress.org, and confirm the fix in the Wordfence entry for your version.

Sources: NVD · WordPress.org plugin page
CVSS 10.0CVE-2026-118423Plugin

WP Libre Form 1.5.0.1 accepts PHP file uploads from anyone

The plugin does not check the type of files sent through its forms. An unauthenticated visitor can upload a PHP file to a folder reachable from the web and run it, which means full control of the site. NVD lists version 1.5.0.1 and does not name a fixed release.

DoIf you run this plugin, deactivate it and delete any unexpected PHP files in your uploads folder until the author publishes a fixed version.

Sources: NVD
CVSS 9.8CVE-2026-119516CVE-2026-120844Plugins

Radius Booking and miniOrange OAuth Single Sign On both list critical bugs

Radius Booking through 1.0.20 can be tricked into rebuilding attacker-supplied data as objects. The miniOrange OAuth Single Sign On client through 7.1.3 can give a user the wrong privileges. NVD names no fixed version for either, so check each plugin's changelog before you rely on it.

Sources: NVD · NVD
CVSS 9.9CVE-2026-71550CVE-2026-100358SuiteCRM fixes two critical bugs in versions before 7.15.2 and 8.10.2

One flaw lets a path-traversal value in the workflow controller pull in files it should not (9.9). The other lets an administrator write PHP into a language file that runs on later page loads (9.4). Update to 7.15.2 or 8.10.2.

Sources: NVD · NVD

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

CIGitHub will block pull_request_target workflows in public repos starting December 2

Unless a repository has an Actions policy that allows it, public repositories will stop running workflows triggered by pull_request_target, including safe ones. The trigger has been behind several package compromises, because it runs with the repository's secrets. GitHub is also running two test blocks, on November 9 and November 16 from 16:00 to 18:00 UTC, when affected workflows will fail.

DoSearch your public repos for pull_request_target now, and either move the workflow to a safer trigger or add an Actions event policy that allows that one file before December 2.

Sources: Socket
HostingA trojanized Control Web Panel server binary hides a backdoor that leaves no log entry

XLab found that cwpsrv versions 1.15.10 and 1.24.0 were replaced with a copy that waits for a signed request in a special header and runs commands without logging. XLab counts more than 340,000 exposed CWP instances. Look for the ngx_http_integrity_helper socket and the X-Ngx-Integrity strings, and if you find them, replace the binary and rotate every panel credential.

Sources: BleepingComputer
HostingFake cPGuard updates gave attackers a root shell on about 2,950 hosting servers

Attackers got into the vendor OpsShield and pushed cPGuard 5.88.12 through 5.88.19 for roughly 70 minutes on Monday. The update ran as root and left a hidden root shell. The figures are OpsShield's own. Move to 5.88.25 or later, check the vendor's indicators of compromise, and reset your billing portal password.

Sources: SecurityWeek
Browser

Chrome 157 fixes 213 bugs, seven rated critical, and none are reported as exploited

The release also fixes 77 high-severity bugs. Google does not say any were used in attacks. Update to 157.0.8103.38 or later and restart the browser, then check your Chromium-based browsers and Electron apps for their own updates.

Sources: SecurityWeek

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

Coding agents

A browser extension could drive Claude Desktop through Dispatch and run code on your computer

Forever Security showed that an extension able to run scripts on claude.ai could send Claude Desktop instructions through the Dispatch feature, click every approval button, and get it to install an npm package. The researchers say the flaw can still be exploited and report no real attacks. Remove extensions you do not need, turn Dispatch off if you do not use it, and avoid one personal Claude account across work and home machines.

Sources: The Hacker News
The UK NCSC says AI tools have almost certainly increased how many zero-days get found

The agency says defenders can patch faster with the same tools, but only if the tools are set up well, and that internal patching and testing have to speed up to match. Today's OpenSSH fix is an example of that shorter gap.

Today's checklist

  • Confirm every WordPress site you run is on 7.1.4 or its branch security release, and look in your logs for odd requests during past upgrades.
  • Upgrade Alpine and other musl-based hosts to OpenSSH 10.6p2, restart sshd, or turn off password logins.
  • List the plugins on your sites and check BuddyForms, WP Libre Form, Radius Booking and miniOrange OAuth SSO against the versions above.
  • Search your public repositories for pull_request_target before the November 9 test block.
  • If you run Control Web Panel or cPGuard, check for the indicators listed in the items above.
  • Update Chrome to 157 and put the November 11 Node.js release on your calendar.
