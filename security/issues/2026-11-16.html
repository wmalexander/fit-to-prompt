Monday, November 16, 2026 No. 13 Patch pressure: Elevated

60-second read

  • Four WordPress plugins (Document Library Pro, Advanced Form Integration, Estatik and Give Peer-to-Peer) have critical or code-running bugs, so update or deactivate them.
  • Apache Shiro through 3.0.0 can accept any password for a known user when LDAP login caching is turned on, and 3.0.1 fixes it.
  • Amazon says attackers' AI agents are searching exposed AI apps such as LiteLLM and Dify for provider keys.
  • A new Linux kernel bug called NoisyTCP can crash web servers, and the fix is in the next kernel update.
01

Patch now

Confirmed exploited or critical and easy to reach

CVSS 9.8 v3.1CVE-2026-122662WordPress

Document Library Pro before 4.2.2 can be fed hostile data that the site turns into code objects

NVD lists this as an unsafe handling of untrusted data (object injection) in the Barn2 plugin, scored 9.8 with no login needed. Whether it leads to code running depends on what other plugins and themes are installed, and I did not find a report of exploitation. NVD has not finished its analysis.

DoUpdate Document Library Pro to 4.2.2 or later through your Barn2 account, and deactivate it until you can.

Sources: NVD
CVSS 9.8 v3.1CVE-2026-125769WordPress

Advanced Form Integration 2.11.3 and earlier lets a stranger give themselves more privileges

NVD describes a wrong-privilege-assignment bug in this form-connector plugin, scored 9.8. That kind of bug usually means a visitor can gain an administrator role. NVD gives no more detail yet, and I did not find a report of exploitation. WordPress.org lists 2.11.6 as current.

DoUpdate Advanced Form Integration to 2.11.6, then review the administrator list for accounts you did not create.

Sources: WordPress.org · NVD
CVSS 9.8 v3.1CVE-2026-125795WordPress

Estatik 4.3.6 and earlier can be tricked into loading a file it should not

The real estate plugin builds a file name from a request without limiting it, which NVD calls local file inclusion and scores 9.8. On many servers that lets an attacker run code if they can also place a file on the site. I did not find a report of exploitation.

DoUpdate Estatik to 4.3.7 or later.

Sources: WordPress.org · NVD
CVSS 7.5 v3.1CVE-2026-82568CVE-2026-82663WordPress

Give Peer-to-Peer has two bugs that, per the CVE text, chain into code running with no login

One bug (versions through 2.9.3) lets a visitor slip database commands into the sort parameter. The other (versions through 2.9.5) lets a visitor change a fundraising team's settings and upload media files. The CVE text says the two can be combined for unauthenticated code execution. At least one Peer-to-Peer campaign must exist on the site. Each is scored 7.5.

DoUpdate the Give Peer-to-Peer add-on to a release newer than 2.9.5, and deactivate it until you can.

Sources: NVD 82568 · NVD 82663
02

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 7.3 v3.1CVE-2026-124672WordPress

Burst Statistics before 3.7.5 lets a visitor switch off other plugins' protections for one request

Per NVD, the plugin unloads every other active plugin when a request is not really meant for its own REST API, and an unauthenticated visitor can trigger that. Protections such as REST restrictions, hidden login pages and two-factor checks then do not run for that request. The same release fixes two smaller data leaks.

DoUpdate Burst Statistics to 3.7.5 or later (3.7.5 is current on WordPress.org).

Sources: WordPress.org · NVD
CVSS 7.2 v3.1CVE-2026-125771WordPress

MCP Server for WordPress 2.0.3 and earlier lets a user raise their own privileges

This plugin connects AI assistants to a site. NVD lists a wrong-privilege-assignment bug scored 7.2, and the details are thin so far. I did not find a report of exploitation.

DoUpdate to 2.0.4, the current release, and review which AI tools can reach the site.

Sources: WordPress.org · NVD
No NVD score yetCVE-2026-110960WordPress

Auth Armor 1.0.3 and earlier lets a visitor read stored API keys and take over an admin account

Per NVD, several handlers in the login-security plugin need no login. They leak the site's stored API credentials and let an attacker reset an administrator's enrollment to take the account. NVD has not scored it, and I did not find a fixed version.

DoDeactivate and remove Auth Armor until the author ships a fix, and rotate the API credentials it stored.

Sources: NVD
CVSS 8.1 v3.1CVE-2026-129091WordPressTheme add-on

GrandPrix Core has a file-loading bug, and no fixed version is listed

NVD lists local file inclusion in the Mikado-Themes GrandPrix Core plugin, version 1.0 and earlier, scored 8.1. Because no fix is named, the safest read is that it is unpatched.

DoRemove GrandPrix Core if the theme does not need it, and ask the theme author for a patched release.

Sources: NVD

Node.js, React & Apache watch

The runtime, the front-end framework and the servers under a lot of the web

CVSS 9.1 v4.0CVE-2026-129349Apache ShiroJava

Apache Shiro can let anyone log in as a known user when LDAP login caching is on

Per NVD, Shiro through 3.0.0 accepts any password for a user who has already logged in once, if the app uses DefaultLdapRealm (or JndiLdapRealm) with authenticationCachingEnabled turned on. That setting is off by default, so only apps that turned it on are exposed. An attacker also needs a valid username.

DoUpgrade Shiro to 3.0.1 or later. If you cannot yet, turn authentication caching off for those realms.

Sources: NVD

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

No NVD score yetCVE-2026-99288Linux kernel

NoisyTCP can crash a Linux web server with specially timed network packets

BleepingComputer reports an 11-year-old Linux kernel bug that lets an attacker with no login crash a server running Nginx, Apache or SSH in a default setup. The researcher says it causes a crash only, not code running or data changes, and that the timing is narrow, so a quiet single-queue server can take a long time to hit. The fix was merged into the mainline kernel about two weeks ago. NVD has not scored it.

DoInstall your distribution's next kernel update and reboot. If you cannot yet, the researcher suggests turning off SYN cookies (which weakens flood protection) or limiting the network card to one receive queue.

Sources: BleepingComputer · NVD
05

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

AI-assisted attacksLiteLLMDify

Amazon says attackers' AI agents are hunting for AI provider keys in exposed LiteLLM, Dify and similar apps

Amazon's decoy servers captured records from agents, which it believes with moderate confidence ran on ARTEX, the AI hacking tool the FBI warned about on November 14. The agents scanned for exposed apps such as LiteLLM, One API, Dify, Langflow and Open WebUI, tried default admin keys, unfinished installs and known bugs, then tested the stolen keys. Amazon says it cannot verify the outcomes the agents reported. Separately, Cloudflare says static CI/CD tokens that never expire were the common root cause in ARTEX cases it investigated, including one account-level token with no IP limits.

DoDo not leave AI gateways reachable from the internet with default keys, put provider keys on spending limits, and replace long-lived CI/CD tokens with short-lived ones that have IP restrictions.

Sources: The Hacker News

Today's checklist

  • Update Document Library Pro to 4.2.2, Advanced Form Integration to 2.11.6 and Estatik to 4.3.7.
  • Update or deactivate Give Peer-to-Peer, and remove Auth Armor and GrandPrix Core until fixes ship.
  • Update Burst Statistics to 3.7.5 and MCP Server for WordPress to 2.0.4.
  • Upgrade Apache Shiro to 3.0.1 if any app uses LDAP realms with caching.
  • Make sure no AI gateway or app builder is exposed with default keys, and set spending limits on provider keys.
  • Schedule your distribution's kernel update for NoisyTCP.
