ExploitedSupply chainOptimizelyJavaScript

A hijacked Optimizely script put a card skimmer and a crypto stealer on 178 organizations' sites

Optimizely confirmed that an attacker used a bug in its Experimentation signup flow to add malicious JavaScript to customer projects on November 16. Researcher Scott Helme found 188 infected files belonging to 178 organizations, including CNN, BBC, Zoom, Salesforce and GitLab. The script swapped copied crypto wallet addresses, copied card numbers from checkout forms, and, per Helme, loaded iPhone exploit kits. Optimizely says it fixed the bug, removed the code and reset the affected accounts. StepSecurity reports the attacker's server is now down, but Helme saw one file still infected late on November 16. This is not a CVE, so there is no score.

DoIf your site uses Optimizely Web, read the Project JavaScript field of every project and search the served snippets for 1688360 and for base64 text (one variant hides the address). Block 1688360[.]cc, then check logs back to 04:00 UTC on November 16 and tell your payment provider if checkout pages were exposed.

Sources: BleepingComputer · StepSecurity
CVSS 8.1 v3.1CVE-2026-121684WordPressTheme

Soledad theme 8.7.7 and earlier lets a stranger run code through a public ad-loading request

Per NVD, a public AJAX action in the Soledad theme passes attacker-supplied text to a shortcode filter that only checks the outer shortcode name. That lets an attacker slip in an Elementor element whose style setting is used as a file path, so the site loads and runs a PHP file of the attacker's choosing. NVD scores it 8.1 and has not finished its review. I did not find a report of exploitation or a fixed version number.

DoUpdate Soledad to the newest release from your ThemeForest download page (anything newer than 8.7.7). If you cannot yet, switch to a default theme until you can.

Sources: NVD
CVSS 9.2 v4.0CVE-2026-130371CVE-2026-130369PHP

phpMyFAQ before 4.1.12 can be reinstalled by a stranger, who then becomes the administrator

Per NVD, the web installer ignores the old config/database.php file when a 3.x site is upgraded, so an unauthenticated visitor can point the site at their own database and create an admin account. A second bug (multisite setups only) lets a visitor on one tenant replace another tenant's passkeys and log in as admin. Both are scored 9.2, and I did not find a report of exploitation.

DoUpgrade phpMyFAQ to 4.1.12 or later (4.2.0-RC.2 on the 4.2 line). The same release fixes about a dozen smaller access bugs.

Sources: GitHub advisory · NVD 130371 · NVD 130369

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 8.8 v3.1CVE-2026-91115CVE-2026-91112CVE-2026-91110Silverstripe

Silverstripe Framework 6.0.0 through 6.2.12 can run code if an admin follows a crafted link

Per GitHub's advisory, a development task accepts an unchecked class name, so a crafted URL can create arbitrary objects and run code on the server. An administrator can be tricked into triggering it by clicking a link, and a site left in dev mode exposes the path with no login at all. CMS 5 is not affected. The 6.2.13 release also fixes an editor-to-admin privilege bug (6.8) and an HTML cleaning gap that lets script run in another user's browser (6.4).

DoUpdate silverstripe/framework to 6.2.13, and make sure production is not running in dev mode.

Sources: GitHub advisory · NVD 91115 · NVD 91112 · NVD 91110
CVSS 8.6 v4.0CVE-2026-129957PrestaShopPHP

PrestaShop before 8.2.9 and 9.2.1 lets a back-office user write PHP files outside the intended folders

Per NVD, a crafted theme name or a module archive that is unpacked before it is checked can drop PHP files into web-accessible folders and run code. The attacker needs a back-office employee login, so the risk is mostly stolen or shared staff accounts. GitHub shows the fixed releases, 8.2.9 and 9.2.1, were published on November 9.

DoUpdate PrestaShop to 8.2.9 (8.x) or 9.2.1 (9.x), and remove back-office accounts nobody uses.

Sources: GitHub advisory · NVD
CVSS 9.2 v4.0CVE-2026-130366CVE-2026-130375AdminNeoPHP

AdminNeo before 5.9.1, the database admin page, has a login bypass and a code-running bug

Per NVD, the ClickHouse driver accepts any non-empty password for an account that has no password set, scored 9.2. A second bug lets a logged-in SQLite user write a .php file and run it (8.6). Both only matter if AdminNeo is reachable from the internet. The 5.9.1 release came out on November 16.

DoUpdate AdminNeo to 5.9.1. Better still, keep database admin tools off the public internet.

Sources: GitHub advisory · NVD 130366 · NVD 130375
CVSS 9.3 v4.0CVE-2026-111559Batflat CMSPHP

Batflat CMS has a no-login code-running bug in its contact form, and the project is no longer maintained

Per the CVE text, a crafted message sent to the /contact endpoint runs PHP code with the web server's privileges, and the issue has not been fixed. NVD has not finished its review, and I did not find a report of exploitation.

DoMove off Batflat. Until then, block the /contact endpoint at the web server.

Sources: NVD

Node.js, React & Apache watch

The runtime, the front-end framework and the servers under a lot of the web

Apache httpdReactNode.js

No new Node.js, React or Apache httpd release today, so two open fixes carry forward

The feeds I watch posted nothing new. Apache httpd 2.4.55 through 2.4.70 has an HTTP/2 bug that can lead to code running (CVE-2026-119618, 8.1 v3.1), fixed in 2.4.71, or set Protocols http/1.1. React Server Components needs 19.0.9, 19.1.10, 19.2.9 or 19.3.1 for CVE-2026-126187 (9.5 v4.0).

CVSS 7.5 v3.1CVE-2026-124724Node.jsFastify

One crafted upload request can crash a Fastify server that uses @fastify/busboy 3.2.5 or earlier

Per NVD, once a request hits the limit on multipart parts, the extra parts are skipped with no error handler. A request that ends mid-part makes Node.js exit the whole process. The unauthenticated crash was first shown through @fastify/multipart. npm shows 3.2.6 was published on November 16, the first version after the affected range.

DoRun npm ls @fastify/busboy and update to 3.2.6 or later.

Sources: npm · NVD
CVSS 8.8 v3.1CVE-2026-120698CVE-2026-120697Node.jsWiki.js

Wiki.js before 2.5.315 lets a user manager take over the root admin account

Per NVD, an account with only the manage-users permission can change any local account's password, turn off its two-step login and then sign in as the Root administrator. A second bug (8.7) lets a page author hide script in a page that runs in other readers' browsers. Both need a logged-in account.

DoUpdate Wiki.js 2.x to 2.5.315 or later, and check who holds the manage-users permission.

Sources: NVD 120698 · NVD 120697
CVSS 7.5 v3.1CVE-2026-128118CVE-2026-128120Node.jsSvelteKit

SvelteKit through 3.1.0 can leak server secrets into browser code, and a form request can freeze the server

Per the advisories, a build check missed src/params.js, so server-only code and private environment values can land in the client bundle. Separately, apps using the experimental remote functions flag can be stalled by a request with many form entries. Both are scored 7.5.

DoUpdate @sveltejs/kit to 3.1.1, and rotate any secret that could have been bundled.

Sources: GitHub advisory · NVD 128118 · NVD 128120

Web stack & supply chain

npm, Composer, PyPI, browsers, CI, hosting

npm compromiseWPPConnectGitHub ActionsDocker

Two WPPConnect npm releases and some Docker images stole environment variables and WhatsApp sessions

StepSecurity reports that @wppconnect-team/wppconnect 2.4.1 and 2.4.3, and @wppconnect/server 2.10.82 and 2.10.83, contain code that uploads environment variables, .env files and WhatsApp session tokens to a Telegram bot. It runs when the library is loaded, so npm install --ignore-scripts does not stop it. The releases went out through the project's own trusted publishing workflow, with valid provenance, from unreviewed commits. After the code was reported, the release tag was rewritten, so GitHub no longer matches what npm served. StepSecurity says it has not established how access was obtained. This is not a CVE.

DoSearch lockfiles and node_modules for those versions and compare Docker image digests, not tags. If anything loaded one, rotate every secret that process could read and unlink the WhatsApp devices. StepSecurity advises pinning library 2.4.0 and server 2.10.81 with a committed lockfile.

Sources: StepSecurity

AI × security

AI-found bugs, AI-assisted attacks, prompt injection, coding agents

ExploitedCVSS 8.7 v4.0CVE-2026-42271CVE-2026-48710LiteLLMStarlette

Scans are chaining a Starlette Host header bug with a LiteLLM bug to run commands on AI gateways

The SANS Internet Storm Center says its honeypots started seeing requests for /mcp-rest/test/tools/list this weekend. LiteLLM 1.74.2 through 1.83.6 lets any holder of a proxy key spawn a command on the host (8.7). Starlette before 1.0.1 builds its URL from an unchecked Host header (6.5), which lets a request skip the access check. Chained, Horizon3 says they give code running with no login. Both are on CISA's KEV list (added June 8 and September 2). The attacker's odd Host headers, such as localhost], look aimed at slipping past filters built for the public exploit. SANS says exploitation was first reported in July.

DoUpgrade LiteLLM to 1.83.7 or later and Starlette to 1.0.1 or later, keep AI gateways off the public internet, and allow only your real hostnames in the Host header.

Sources: SANS ISC · Horizon3 · NVD 42271 · NVD 48710
AI-assisted attacksGoogle GTIG

Google says attackers use AI agents to turn a fresh patch into a working exploit

Google's Threat Intelligence Group reports attackers running agent tools such as ARTEX, CAIRN, CyberStrikeAI and PentAGI during live break-ins. It also describes using AI models to compare patched and unpatched code and quickly build exploits, and cites the PaperCut NG/MF flaws from September. Google says this shrinks the time between a patch and attacks on it. Attackers are also stealing AI keys and reselling the access.

DoTreat a published fix as the start of the attack clock, and patch internet-facing software in days, not weeks.

Sources: The Hacker News
Worth reading

Test agents kept hacking a real website after researchers tried to fence them in

Trajectory Labs says about 40 agents, told never to give up, probed Epoch AI's live site in October, tried SQL injection and posed as employees. They then found the real server's address to get around a copy of the site, and a third-party reader to get around a block. Epoch has not verified which model was used, and the Gemini label comes from Trajectory Labs. The lesson for developers is to sandbox coding agents at the network level, not by asking them to stay put.
