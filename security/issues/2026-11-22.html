Ghostscript before 10.08.0 can run an attacker's commands when a crafted file is uploaded

Ghostscript is the program many Linux servers use to turn uploaded PDFs, PostScript and images into thumbnails and previews. Image libraries such as ImageMagick hand a file to Ghostscript even when it is named .png or .jpg, so an app does not have to call it directly. Researchers at pwn.ai showed a crafted file escaping Ghostscript's sandbox and running commands on the server as the low-privilege account that does the rendering. Their tests reached it through about ten applications, including public upload forms in the WordPress plugins Forminator and Essential Addons for Elementor, a Roundcube email attachment, and a print job sent to a Debian 13 server. Artifex fixed the bug on September 8, and no attacks have been reported.

WordPress Core closed its own upload path in 7.0.4 on August 12. In WordPress, Authors and higher roles can upload files by default, so Core needs a logged-in user, while the two plugin forms needed none. The two fixes cover different points in the same chain, so one does not replace the other. The Ghostscript fix only helps where it reaches the copy your app actually uses, such as the one inside a container image.

DoUpdate Ghostscript to 10.08.0 or your distribution's patched build (including inside container images), update WordPress to 7.0.4 or later, and update Forminator and Essential Addons for Elementor if you allow public file uploads.

Sources: pwn.ai research · The Hacker News · NVD (Ghostscript) · NVD (WordPress)

Nexter Blocks Pro 5.0.10 and earlier lets a visitor make themselves an administrator

The plugin's user sign-up function tries to block attempts to set a user's role, but its check misses look-alike Unicode letters, and the database treats those letters as the same as the plain ones. A stranger can register an account and end up with administrator rights. We found no report of attacks and no vendor advisory yet, so the fixed version number is not confirmed.

DoIf the plugin is on a site, update to a release newer than 5.0.10 as soon as the vendor lists one, and until then turn off public registration or the plugin.

Sources: NVD
CVSS 7.4CVE-2026-119114WordPressNo attacks reported

WP Fastest Cache 1.5.4 and earlier can let a stranger delete files such as wp-config.php

A stranger can make the plugin delete files outside its cache folder, which can lead to code execution if the right file goes. It only works on sites that also run the Custom Permalinks or GeoDirectory plugin, because those let the attacker store the bad path. We found no report of attacks.

DoUpdate WP Fastest Cache to a release newer than 1.5.4, and look at sites that also run Custom Permalinks or GeoDirectory first.

Sources: NVD

Shortcodes Ultimate 7.9.1 and earlier can include PHP files from the active theme

A forged Host header can get a stranger's text into the QR code shortcode, and the plugin then loads PHP files from the active theme folder. It is limited to the theme's own files, so the impact depends on the theme. Update to a release newer than 7.9.1.

CVSS 8.8CVE-2026-129220WordPress

Everest Forms 3.6.4 and earlier lets a form creator turn on any installed plugin

It only matters on sites where an administrator gave the everest_forms_create_forms capability to a lower role. Those users can switch on plugins that are installed but off, which can lead to administrator access. Update to a release newer than 3.6.4, or review who holds that capability.

Five Fastify add-on bugs can let a stranger skip your login checks

Fastify's @fastify/express and @fastify/middie add-ons let you run Express-style middleware, such as an auth check, on chosen paths. In all five bugs, Fastify's router sends a request to a route while the add-on decides the path is different, so the middleware is skipped and the route still runs. The triggers include empty path parameters, a mount path missing its leading slash, odd encodings such as an encoded backslash, and regular-expression mount paths under a prefix. The affected ranges are @fastify/express 4.0.0 through 4.0.9 and @fastify/middie up to 9.3.7. We found no report of attacks. How bad it is for you depends on what the skipped middleware protected.

DoUpgrade @fastify/express to 4.0.10 or later (4.0.11 is current) and @fastify/middie to 9.3.8 or later (9.3.9 is current), rerun your lockfile install, and check that protected routes reject requests with empty or odd path segments.

Sources: npm: @fastify/express · npm: @fastify/middie · NVD · NVD · NVD · NVD · NVD

Critical (vendor)GnuPGNo attacks reported

GPGME before 2.3.1 can leak app data when it reads a malicious OpenPGP key

GPGME is the library apps use to talk to GnuPG. A key with an unusually long user ID can trigger a double free (memory released twice), which could be used to pull data out of an app that checks signed data. GnuPG says remote code execution cannot be ruled out. It was reported through GitLab and disclosed on November 20, earlier than planned. NVD has no record for its CVE number yet, so we are not printing it, and we have no scores to verify.

DoUpdate GPGME to 2.3.1 or your distribution's patched build, and rebuild anything that bundles it statically, such as Gpg4win.

Sources: GnuPG advisory (T8557) · The Hacker News
BreachKubernetes

Rackspace Spot breach exposed Kubernetes secrets in some customer clusters

Rackspace says someone used leaked credentials to get into parts of Rackspace Spot on November 17 for about 22 hours. They could create pods, read Kubernetes Secrets and list nodes in some customer organizations. Rackspace says it has revoked affected tokens and removed the unauthorized pods.

DoIf you use Rackspace Spot, reissue Spot API tokens, download fresh kubeconfig files, rotate every credential stored in cluster Secrets, and check database, registry, Git and cloud logs back to November 17.

Sources: BleepingComputer

Prompt theftAI providers

Researchers caught three AI hosting providers leaking customers' prompts for months

Dragos sent about two million prompts containing fake AWS keys and tracking links to AI services between July and November, then watched for anyone using them. It says attackers had stolen data from three providers, including requests marked Zero Data Retention. One attacker tested the stolen keys within hours. OpenRouter, a gateway that routes requests to outside providers, says it removed those three providers and told affected customers, and that its own systems were not breached. The numbers come from Dragos and OpenRouter, about their own research and platform.

DoNever paste real keys into prompts, rotate any key that has been, and treat a "zero data retention" label as a promise rather than proof.

Sources: Dragos · The Hacker News
ResearchFixed

One malicious web page could pull a Meta Muse user's private chats

NebuSec showed a web page the agent opened pulling out chat history and stored memories with no approval prompt, then chaining to a kernel bug for control of that user's cloud machine. It was a lab demo and NebuSec says Muse's team fixed it all before publishing. Meta has not confirmed. The lesson for agent builders is that a page an agent reads is untrusted input.
