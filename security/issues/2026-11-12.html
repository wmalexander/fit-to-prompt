Red Hat 9.8CVE-2026-119618Apache httpd

Apache's HTTP/2 module has a critical bug that can let a stranger run code on the server

A timing bug in mod_http2 can corrupt memory and lead to remote code execution with no login. It affects Apache HTTP Server 2.4.55 through 2.4.70, and the standalone mod_h2 module from 2.0.8 through 2.0.42. Only servers with HTTP/2 turned on are exposed, which means a Protocols line that lists h2 or h2c, server-wide or in any virtual host. NVD has no score yet; the 9.8 is Red Hat's rating, and Red Hat labels it Important on RHEL 9 and 10 because its builds make the attack harder. The sources disagree on proof: Red Hat says public research shows a reliable exploit, while Wiz says no exploit is available and no attacks have been reported. I found no CISA listing. Wiz also says 64% of the cloud environments it sees run a vulnerable version, which is the vendor's own figure.

DoRun httpd -v (or apache2 -v) and upgrade to 2.4.71. On a distro package, install the vendor's fix instead: RHEL 9 ships mod_http2-2.0.26-7.el9_9.1 and RHEL 10 ships mod_http2-2.0.29-5.el10_3.1, while Debian bookworm and trixie had no fix listed when I checked. If you cannot patch today, set Protocols http/1.1 and remove h2 and h2c everywhere, then reload.

Sources: Apache advisory · Red Hat · Wiz · The Hacker News · NVD
CVSS 8.2 v3.0CVE-2026-123863CVSS 8.1 v3.0CVE-2026-123864CVSS 7.5 v3.0CVE-2026-123866Node.js

Node.js fixes 16 flaws, including ones that crash servers and leak other users' data

CVE-2026-123863 lets any client crash a default HTTP/2 server that replies before the request body arrives. CVE-2026-123866 can make an HTTP/2 server send a client pieces of memory, including other connections' responses. CVE-2026-123864 can expose TLS private keys and other users' requests on HTTPS servers, but only when a handler calls res.flushHeaders() early and later calls res.end() with data. Seven of the 16 are rated high. Plain node:http servers are not affected by the HTTPS bug. The project lists no workaround and reports no attacks, and it does not say whether to replace TLS keys after updating. End-of-life lines such as 20.x and 25.x get no fix.

DoUpgrade to 22.23.5, 24.22.3 or 26.13.1, and move off 20.x and 25.x. If a Node process terminates TLS or HTTP/2 itself and has a handler like the one above, consider replacing its TLS key as a precaution.

Sources: Node.js advisory · The Hacker News · NVD 123863 · NVD 123864 · NVD 123866
Active campaignGitHub Actionsnpm

Stolen GitHub logins are being used to plant a secret stealer in CI workflows

Starting November 10, an attacker with stolen tokens for thousands of accounts opened pull requests titled docs: dependency audit notes from a wfx-docs branch, then pushed a script that copies the secrets and cloud credentials a workflow can reach and reverts the change within minutes. Aikido counts 1,806 or more repositories where it ran; SafeDep counts 8,093 that received malicious commits. It is not a GitHub bug, and the source of the stolen tokens is unexplained. StepSecurity says new copies now send data only to Telegram, so blocking the published IP addresses no longer helps.

DoSearch every repository you can write to for the branch wfx-docs and for commits titled ci: refresh build cache, chore: add ci helper or chore: add dependency audit workflow. A missing run number in the Actions tab after such a commit means it probably ran. If you find one, rotate every secret and cloud role the workflow could reach, revoke the author's tokens and keys, and turn on 2FA.

Sources: StepSecurity · Aikido · The Hacker News

WordPress & PHP watch

Core, plugins, themes, PHP and the frameworks on top of it

CVSS 9.8 v3.1CVE-2026-121497WordPress

AskAny lets strangers upload PHP files and run code

Per NVD, the AskAny plugin before 2.2.0 trusts the file type the browser reports on chat attachments, so an unauthenticated visitor can upload a PHP file and run it. It only applies when visitor attachments are turned on.

DoUpdate AskAny to 2.2.0 or later. If you cannot, turn off visitor attachments or deactivate the plugin, and look for unexpected .php files in its upload folder.

Sources: NVD
CVSS 9.8 v3.1CVE-2026-123695WordPressWooCommerce

Security For WooCommerce lets anyone log in as any user, including admins

Per NVD, the plugin leaves several REST routes open, so an unauthenticated visitor can generate login tokens for every user, fetch them, and sign in as an administrator. It affects versions through 1.0.16, and I found no fixed version listed.

DoDeactivate and remove Security For WooCommerce until the author ships a fix. Check the user list for administrators you do not recognize and reset passwords for existing admins.

Sources: NVD
CVSS 9.1 v3.1CVE-2026-126537WordPress

Ninja Forms File Uploads add-on can be used to delete or read server files

NVD says versions up to 3.3.36 let a public form submission point the add-on at a file path of the attacker's choosing, which can delete that file or send it out through S3, Dropbox or Google Drive. NVD marks the entry deferred, and I found no fixed version, so update to the newest release and check its changelog.

CVSS 8.8 v3.1CVE-2026-118041WordPress

Contest Gallery lets an author-level user upload files that run as code

Per NVD, versions before 34.0.3 do not clean file names in the sale file-replacement feature, so a user with Author access or above can write a file with any name and reach remote code execution. Update to 34.0.3 or later and review who holds Author roles.

Node.js, React & Apache watch

The runtime, the front-end framework and the servers under a lot of the web

CVSS 8.8 v3.1CVE-2026-118411Apache Roller

Apache Roller can be tricked into creating an attacker's admin account

Per NVD, Roller 5.0.1 through 6.1.6 only checked the request token on POST requests, but admin actions also accepted GET. If a logged-in admin opens a link the attacker controls, a new administrator account can be created. Upgrade to Roller 6.1.7 or later.

Still openCVE-2026-126187React

Yesterday's React Server Components fix still needs checking in your apps

The critical bug (9.5, CVSS v4.0) in react-server-dom-webpack, react-server-dom-parcel and react-server-dom-turbopack is fixed in 19.0.9, 19.1.10, 19.2.9 and 19.3.1. React says it applies only in rare cases, and I found no new reports of attacks today. Frameworks such as Next.js can bundle their own copy, so check their release notes too.

Web stack & supply chain

ResearchCSP

A Content Security Policy that trusts the wrong host can still let attackers steal logins

PortSwigger describes two common mistakes. A script allow-list that names a host serving a JSONP endpoint or an old AngularJS copy lets an attacker load code from an allowed origin, and PortSwigger's new Burp AT skill checks policies against a list of more than 350 known examples. A policy that does not restrict form-action lets an injected form send typed credentials to an attacker even when no script runs, because form-action does not fall back to default-src.

DoOpen your site's Content-Security-Policy header, add an explicit form-action 'self', and remove wildcard or CDN hosts from script-src in favor of nonces or hashes with strict-dynamic.

Sources: PortSwigger Research

AI × security

AI-assisted attacksAWS

Attackers are running an AI pentest tool to steal AWS keys from web servers

Arctic Wolf reports attackers hosting the open-source AntiFox agent platform on Alibaba Cloud, using it to deploy webshells, read config files and database connection strings, and then call AWS with valid IAM keys. In one case they made hundreds of API calls in about 30 minutes. AWS says its services were not compromised and that the keys came from customers' compromised applications.

DoKeep AWS keys out of app config files, remove unused IAM users, and review CloudTrail for bursts of denied calls followed by a success.

Sources: BleepingComputer · The Hacker News · Unit 42
AI-built appsGrok

Most apps built with Grok's chat builder are open to anyone, and some hold private data

Claroc found 37,571 Grok-built apps online, and 35,578 needed no sign-in. About 1 in 10 held internal business or personal data, and the researchers estimate roughly 2% held high or critical material. The share-with-anyone-who-has-the-link option was preselected, and app addresses can be found through DNS records. These figures come from the researchers' own report.

DoIf you or your staff publish apps from an AI builder, set access to "Only you" or "Invited users" and move any password or customer data out of the app.

Sources: The Hacker News
ResearchAI agents

Microsoft shows a coding agent's model can be backdoored by editing fewer than 10 neurons

The attacker has to be able to change the model's weights. A chosen trigger, such as a tool error, then makes the model output a command the agent runs with its own permissions. Microsoft says it has not seen attackers use it. The practical advice is to download models only from sources you trust and to limit what an agent is allowed to run.

Worth readingUnit 42

Unit 42 counts more than 1,900 exposed AI red-team tool servers

As of October, Unit 42 found 1,323 internet-facing hosts running CyberStrikeAI and 609 running ARTEX, and it describes attackers using these tools against login and API workflows to reach cloud accounts. It is a short read on what defenders should watch for.
