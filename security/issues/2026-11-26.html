Last week's Drupal installer fix left a gap, and attackers are using it

Drupal core includes an installer that sets up new sites. The Nov 18 update closed one way to abuse it (CVE-2026-132165, on CISA's exploited list since Nov 24). On Nov 25 Drupal said some sites in unusual or incomplete install states, including production sites, can still be taken over, and that this second bug (CVE-2026-136716) is also being exploited. The UI does not show whether a site is in the affected state. Drupal rates it 21 out of 25 on its own scale. NVD has no CVSS score for either bug yet. Sites whose installer was already locked down are not affected.

DoUpdate to Drupal 11.4.14, 11.3.23 or 10.6.23, and on production sites run the update hook after upgrading. Check logs for installer requests and for new admin accounts, since a site that was already hit may no longer look vulnerable.

Sources: SecurityWeek · BleepingComputer · StepSecurity · NVD CVE-2026-136716 · NVD CVE-2026-132165
CVSS 9.8 (v3.1)CVE-2026-125812WordPressWP Rocket

WP Rocket before 3.24.2 has a critical path traversal bug

A path traversal flaw lets a request reach files outside the folder the plugin means to use. NVD scores it 9.8 and lists every version before 3.24.2 as affected. The record gives no detail on how it is triggered, and I found no report of attacks, so treat this as a patch-soon item for the most widely installed paid caching plugin.

DoUpdate WP Rocket to 3.24.2 or later on every site that runs it.

Sources: NVD (the only public source found at build time)
Reported exploitedCVSS 9.2 and 9.5 (v4.0)CVE-2026-133335CVE-2026-133336Joomla

Two Joomla extensions let strangers run or upload code

VirtueMart 4.0.0 to 4.8.7 includes any PHP file a visitor names, which can lead to code execution depending on server setup; its CVE record says it has been exploited in the wild. ChronoForms 8.0.0 to 8.0.53 checks the wrong filename on uploads, so an unauthenticated visitor can upload a dangerous file type.

DoUpdate VirtueMart to 4.8.8 and ChronoForms to 8.0.54, then look for PHP files you did not add in upload and cache folders.

Sources: NVD CVE-2026-133335 · NVD CVE-2026-133336

CVSS 10.0 (v4.0)CVE-2026-78114Apache JSPWiki

Apache JSPWiki: login keeps the same session ID, fixed in 3.0.1 and 2.12.6

JSPWiki 2.10 through 3.0.0 did not issue a new session ID when someone logged in, so an attacker who could plant a known ID in a victim's browser could reuse it afterward. NVD shows a 10.0 score from the reporting CNA, which looks high for this kind of bug, so read the advisory before you rank it. Upgrade to 3.0.1 or 2.12.6. The Node.js, React and Next.js feeds had nothing new today.

ExploitedCVSS 10.0 (v4.0)CVE-2026-129514Hex.pm

Attackers ran commands on six Hex.pm registry servers

Hex.pm is the package registry for Elixir and Erlang. A bug in how it read one kind of request body, present since 2016, let an unauthenticated attacker run commands on six production servers on Nov 23. The maintainers patched within about 15 minutes and found no sign any package was changed, but they could not rule out that account emails, password hashes and two-factor secrets were read. Everyone was logged out. The registry signing key has not been replaced yet.

DoIf you have a hex.pm account, change the password, set up two-factor again, and log back in with mix hex.user auth or rebar3 hex user auth. Fetch only from repo.hex.pm until the new client ships.

Sources: The Hacker News · NVD
Supply chainGitHub

1Password: one hacked GitHub account led to stolen customer records

An attacker used an employee's GitHub account to push code into backend services that pulled customer account records. 1Password says vaults and their keys were not touched, and that only a small number of users were affected and have been told directly. The lesson for any team is how much one developer account on GitHub can reach.

AI-driven attacks

Italy and Switzerland warn of AI agents hacking in parallel

Italy's CSIRT says autonomous AI agents found and exploited exposed systems at scale, in one case five agents working together within hours. Switzerland reports its first successful AI-assisted attacks. Both agencies advise patching internet-facing systems first and closing remote management pages.

Worth readingWiz Research

Wiz: attack tools leak a counter you can search your logs for

Wiz says two families of AI attack tools, ARTEX and Cairn, number each sub-goal and the model copies that number into file names, workflow names and account names, such as i19ghci.yml. Defenders can use the pattern to link attacks across rotating IP addresses. This is the vendor's own research.
